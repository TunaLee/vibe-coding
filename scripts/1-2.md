지도 한번 보고 가겠습니다. 1-1에서 개념을 봤고, 현재 1-2 도구 준비입니다. 이어서 1-3 기획서, 1-4 개발 계획, 1-5 Git과 GitHub, 1-6에서 드디어 앱을 만들고, 1-7에서 배포해서 공유 주소를 받습니다. 1-8에서 돌아보고 2부로 넘어가요. 모든 단원은 「미니 노션」이라는 같은 예제로 제가 먼저 보여 드리고, 여러분은 같은 순서로 자기 아이디어를 만듭니다.

## 30 · 1부 실습 도구
1부에서 쓰는 도구는 세 개뿐입니다. 아이디어 고르기부터 기획서, 개발 계획, 앱 코드까지 전부 Claude Code 하나로 합니다. 대화창 AI에서 아이디어 정리하고, 그걸 복사해서 다른 도구로 옮기고… 그런 거 안 합니다. 같은 일을 두 번 할 이유가 없으니까요. GitHub는 코드와 변경 기록을 보관하는 곳, Vercel은 만든 앱을 인터넷 주소로 공개해 주는 곳입니다. 화살표 순서가 그대로 1부 작업 순서예요. 이름이 다 영어라 벌써 머리 아프신 분, 세 개만 넘기면 더 안 늘어납니다.

> 곁들일 이야기 — 가게를 하나 연다고 해 보죠. 상담부터 공사까지 한 번에 해 주는 시공사(Claude Code), 설계도랑 공사 기록 넣어 둘 창고(GitHub), 손님이 찾아올 간판과 주소(Vercel). 상담 따로, 공사 따로 맡기면 같은 설명을 두 번 해야 하잖아요.

## 31 · Claude와 Claude Code
그럼 왜 굳이 Claude Code일까요. 이름이 거의 똑같은 Claude 대화창도 있는데요. 1-1 「AI 코딩 도구의 변화」에서 본 대화형과 위임형 차이입니다. 「미니 노션 만들어 줘」, 같은 요청을 두 도구에 똑같이 해 보겠습니다. 위쪽 Claude는 코드를 글로 답해 줍니다. 그다음부터는 사람 일이에요. 코드 복사하고, 파일 만들어 붙여 넣고, 저장해서 브라우저로 열고, 오류 나면 다시 물어보고. 사람 손이 네 번 갑니다. 아래쪽 Claude Code는 폴더 파일을 직접 읽고, index.html을 만들고, 실행해서 확인하고, 오류도 알아서 고칩니다. 사람은 마지막에 결과만 봐요. 차이는 딱 하나, 내 컴퓨터 파일에 AI 손이 닿느냐입니다. 그래서 이 강의는 처음부터 끝까지 Claude Code 하나로 갑니다.

> 곁들일 이야기 — 예를 들어 전화로 요리법을 듣는 것과, 요리사가 우리 집 부엌에 와서 직접 해 주는 것의 차이예요. 전화로는 아무리 친절하게 알려 줘도 양파는 내가 썰어야 합니다.
> 곁들일 이야기 — 엑셀 수식을 챗봇에 물어보고, 복사해서 셀에 붙였더니 오류, 다시 묻고 또 붙이고. 해 보신 분 많으시죠? 위쪽 줄이 바로 그 과정입니다.

## 32 · Claude Code 사용 환경
Claude Code는 쓰는 곳이 여러 군데입니다. 검은 명령어 창, 터미널에서 쓰는 방식이 기능이 제일 많고요. VS Code 같은 편집기에서는 확장 프로그램으로, JetBrains 편집기에서는 플러그인으로 씁니다. macOS랑 Windows용 데스크톱 앱도 있고, claude.ai/code에서 웹으로 클라우드에서 돌릴 수도 있어요. 어디서 쓰든 안에서 도는 엔진과 설정은 같습니다. 이 강의는 파일을 눈으로 보면서 작업할 수 있는 VS Code를 기본으로 갑니다. 검은 창이 무서우신 분들, 안심하셔도 됩니다.

> 곁들일 이야기 — 카카오톡을 휴대폰에서 쓰든 PC에서 쓰든 같은 계정, 같은 대화방이 보이잖아요. 화면 모양만 다르고 안에 있는 건 똑같습니다.

## 33 · VS Code
VS Code 화면은 네 구역입니다. 왼쪽 ① 탐색기는 폴더 안 파일 목록, 가운데 ② 편집기는 파일 내용. 아래 ③ 터미널은 명령어 치는 창이고, 오른쪽 ④가 Claude Code랑 대화하는 패널이에요. 여러분은 주로 ④에서 말을 걸고, ①과 ②에서 뭐가 바뀌었는지 확인하게 됩니다. 말은 오른쪽에서, 감시는 왼쪽에서. 이렇게 기억하시면 됩니다.

> 곁들일 이야기 — 윈도우 탐색기나 맥 Finder로 폴더를 열어 두고, 옆에 메모장 띄우고, 또 옆에 메신저 창 하나 더 열어 둔 모습을 한 화면에 모았다고 보시면 돼요.
> 곁들일 이야기 — VS Code는 Microsoft가 무료로 배포하는 편집기입니다. 개발자들이 가장 많이 쓰는 편집기 가운데 하나라서, 막혔을 때 검색하면 자료가 금방 나옵니다.

## 34 · 확장 프로그램
VS Code는 처음 깔면 기본 기능만 있고, 필요한 건 확장 프로그램으로 붙입니다. 휴대폰으로 치면 VS Code가 휴대폰, Marketplace가 앱 스토어, 확장 프로그램이 앱이에요. 순서도 같습니다. ① 검색창에 이름 치고, ② 목록에서 고르고, ③ Install 누르고. 앱 깔아 보신 분이면 이미 다 아시는 겁니다.

> 곁들일 이야기 — 크롬에 번역이나 광고 차단 기능을 확장 프로그램으로 붙여 보신 분? 그분들은 사실상 오늘 실습 하나를 미리 하신 겁니다.

## 35 · Claude Code 확장 설치
실제로 Claude Code 확장 까는 순서입니다. ① 왼쪽 확장 보기를 엽니다. 맥은 Shift·Command·X, 윈도우는 Ctrl·Shift·X예요. ② 검색창에 Claude Code 치고, 만든 곳이 Anthropic인지 꼭 확인합니다. ③ Install 누르면 ④ 번개 모양 Spark 아이콘이 생기고, 그걸 눌러서 로그인합니다.

> 곁들일 이야기 — 앱 스토어에서 은행 앱 받을 때 비슷한 이름이 여러 개 뜨면 개발사부터 보시잖아요. 확장 프로그램도 똑같습니다. 이름 비슷한 게 여럿 보일 수 있으니 「Anthropic」 꼭 확인하세요.

## 36 · Claude Code 기본 조작
실습 들어가기 전에 Claude Code 패널 쓰는 법만 딱 1분 보고 가죠. 여섯 개만 알면 됩니다. 입력창에 요청을 쓰고 Enter. 입력창 아래 모드 표시를 누르면 Manual, Plan, Auto 같은 모드를 고를 수 있어요. 처음엔 Manual, 수정할 때마다 물어보는 모드로 갑니다. 「/」를 치면 명령 메뉴가 열리고, 「@」 다음에 파일 이름을 쓰면 그 파일을 읽고 답합니다. 「@기획서.md 읽고 요약해 줘」처럼요. 잘못 고쳤으면 메시지에 마우스를 올려 되돌리기 버튼을 누르면 되고, 답이 엉뚱한 데로 가면 바로 멈추고 다시 요청하세요. 이 정도면 오늘 실습은 충분합니다.

## 37 · 실습 1-2 ① 순서
첫 번째는 가입과 설치입니다. claude.ai에 가입하고 요금제 확인. github.com 가입하고, vercel.com에서는 「GitHub로 계속하기」를 누릅니다. 그다음 VS Code 깔고, 확장에서 Claude Code 깔고, 마지막으로 바탕화면에 workspace와 mini_notion 폴더를 만듭니다. 세 사이트 다 로그인돼 있고 VS Code 오른쪽 위에 Spark 아이콘이 보이면 다음으로 넘어가시면 됩니다. 자주 막히는 데가 두 군데 있어요. GitHub 가입할 때 이메일 인증 코드를 안 봐서 진행이 멈추는 경우, 그리고 Vercel에서 GitHub 말고 이메일로 가입해 버리는 경우입니다. 「어, 안 넘어가는데요?」 하시면 십중팔구 이 둘 중 하나예요.

> 곁들일 이야기 — 브라우저 탭 세 개를 나란히 열어 두고, 각각 로그인돼 있는지 눈으로 보는 게 제일 빠른 점검법입니다.

## 38 · 실습 1-2 ① · 1단계 Claude 가입 · 요금제
첫 단계, Claude 가입입니다. claude.ai에 들어가서 Google 계정이나 이메일로 가입하시면 됩니다. 여기서 제일 중요한 건 요금제예요. 화면에 표시한 Pro 이상이어야 Claude Code를 쓸 수 있습니다. Free로 가입하면 가입까지는 잘 되는데, 나중에 Claude Code 로그인에서 딱 막힙니다. 「저만 안 돼요」의 1순위 원인이니까 지금 꼭 확인해 주세요.

## 39 · 실습 1-2 ① · 2단계 GitHub 가입
다음은 GitHub. github.com에서 Sign up을 누르고 이메일, 비밀번호, 사용자 이름을 넣습니다. 사용자 이름은 나중에 저장소 주소에 그대로 들어가니까 너무 장난스럽게 짓지는 마세요. 그리고 여기서 제일 많이 멈추는 곳, 이메일 인증 코드입니다. 메일함에 코드가 와 있는데 안 보고 화면만 쳐다보고 계신 분이 꼭 계세요.

## 40 · 실습 1-2 ① · 3단계 Vercel 가입
Vercel은 버튼 하나만 기억하시면 됩니다. Continue with GitHub. 방금 만든 GitHub 계정으로 들어가는 거예요. 위에 Google, 아래에 ChatGPT, Apple 버튼도 보이는데, 손이 미끄러져서 다른 걸 누르면 나중에 GitHub를 따로 연결해야 해서 일이 늘어납니다. 비밀번호를 또 만들 필요도 없어요.

## 41 · 실습 1-2 ① · 4단계 VS Code 설치
이제 프로그램을 깝니다. VS Code 다운로드 페이지예요. 맥 쓰시는 분은 macOS, 윈도우 쓰시는 분은 Windows 버튼을 누르세요. 윈도우는 User Installer가 받아지고, 맥은 .dmg 파일이 받아집니다. 내 컴퓨터가 뭔지 헷갈리시면 옆 사람 말고 화면 왼쪽 위 사과 모양이 있는지 보시면 됩니다.

## 42 · 실습 1-2 ① · 4단계 Claude Code 확장
VS Code를 열었으면 확장에서 Claude Code를 설치합니다. 맥은 Shift+Command+X, 윈도우는 Ctrl+Shift+X로 확장 화면을 열고, 「Claude Code」를 검색하세요. 만든 곳이 Anthropic인지 꼭 보시고요. 비슷한 이름의 다른 확장도 있거든요. 그리고 Install. 끝입니다.

## 43 · 실습 1-2 ① · 5단계 작업 폴더 만들기 · 열기
마지막은 작업할 폴더입니다. 바탕화면에 workspace 폴더를 만들고, 그 안에 mini_notion 폴더를 하나 만드세요. 윈도우는 탐색기를 Win+E로 열고 바탕 화면에서 Ctrl+Shift+N, 맥은 Finder에서 데스크탑으로 가서 Shift+Command+N입니다. 윈도우 회사 PC는 바탕 화면이 OneDrive 안에 들어가 있는 경우가 많으니, 탐색기 왼쪽의 「바탕 화면」을 눌러서 만드세요. 그리고 바로 VS Code에서 File, Open Folder로 mini_notion을 엽니다. 맥은 Command+O, 윈도우는 Ctrl+K 누르고 Ctrl+O. 오늘부터 1-7까지 이 폴더 하나로 갑니다. 열어 둔 채로 다음 실습으로 넘어가요.

## 44 · 실습 1-2 ② 순서
폴더를 열었으면 두 번째 실습입니다. 세 단계예요. 폴더를 처음 열면 신뢰 창이 뜨니까 Yes, Spark 아이콘으로 Claude Code를 열고 로그인, 그리고 첫 요청. 「이 폴더에 뭐가 있는지 알려 줘」라고 물어서 답이 오고, 파일이 새로 생기지 않았으면 성공입니다.

## 45 · 실습 1-2 ② 요청 항목
첫 요청에는 세 가지를 담습니다. 목표는 이 폴더가 현재 어떤 상태인지 듣는 것, 범위는 이 폴더 안만, 하지 말 것은 아직 파일 만들지 않기. 요청이 짧아도 「하지 말 것」 한 줄을 넣으면 AI가 앞서 나가지 않아요. 이 세 항목, 앞으로 실습할 때마다 계속 씁니다. 지금 입에 붙여 두세요.

> 곁들일 이야기 — 예를 들어 새로 온 동료한테 「이 공유 폴더에 뭐 있는지만 먼저 훑어봐 줘. 정리는 아직 하지 말고」라고 하는 거죠. 이 말 없이 「폴더 좀 봐 줘」만 하면, 의욕 넘치는 동료는 파일 옮기고 이름까지 싹 바꿔 놓기도 합니다. 고맙긴 한데 내 파일을 못 찾아요.

## 46 · 실습 1-2 ② · 1단계 폴더 신뢰
방금 폴더를 열었을 때 이런 창이 떴을 거예요. 「이 폴더의 파일을 만든 사람을 믿느냐」. 내가 방금 만든 폴더니까 Yes, I trust the authors. 화면 예시는 윈도우 경로인데 맥도 같은 창이 뜹니다. 남이 준 폴더를 열 때는 한 번쯤 생각해 보라고 묻는 거예요.

## 47 · 실습 1-2 ② · 2단계 Claude Code 열기 · 로그인
편집기 오른쪽 위를 보시면 주황색 Spark 아이콘이 있습니다. 이걸 누르면 Claude Code 패널이 열려요. 처음이면 로그인하라고 합니다. Claude 계정을 고르면 브라우저가 뜨고, 거기서 승인하면 다시 VS Code로 돌아옵니다. 아까 말씀드린 대로 Free 계정이면 여기서 막혀요.

## 48 · 실습 1-2 ② · 3단계 첫 요청 · 답 읽기
이제 첫 요청입니다. 패널 아래 입력창에 요청을 쓰고 Enter. 요청 항목에서 본 대로, 이 폴더에 지금 뭐가 있는지 알려 달라고, 파일은 아직 만들지 말라고 쓰시면 됩니다. 답은 패널 가운데에 나옵니다. 빈 폴더라 「비어 있다」는 답이 나올 거예요. 왼쪽 탐색기에 새 파일이 안 생겼는지까지 보시면 첫 요청 성공입니다.

## 49 · 실습 1-2 ③ 순서
세 번째 실습은 일부러 대충 시켜 보는 실습입니다. 진짜예요. 같은 mini_notion 폴더에서 Claude Code한테 「미니 노션 만들어 줘」 딱 한 줄만 보냅니다. 기능, 화면, 저장 방식 같은 건 하나도 덧붙이지 마세요. 손이 근질근질하셔도 참으세요. 파일 만들기를 승인하고, 결과 보고를 읽고, 브라우저로 열어서 내 생각과 비교합니다. 다른 곳을 세 가지 찾으면 성공이에요. 그리고 마지막에 파일은 지웁니다.

## 50 · 실습 1-2 ③ · 1단계 한 줄 요청
제가 실제로 보낸 요청입니다. 「미니 노션 만들어 줘」. 끝입니다. 이렇게 짧게 보내도 되나 싶으시죠? 보내 보세요. 일단 뭔가 만들긴 합니다. 문제는 그게 뭐냐는 거죠.

## 51 · 실습 1-2 ③ · 2단계 파일 만들기 승인
잠시 뒤 index.html을 만들어도 되냐고 묻습니다. 무려 282줄짜리 파일 하나예요. 1번은 이번만 승인, 2번은 이 대화 동안 파일 수정은 자동 승인. 저는 2번을 골랐습니다. 코드를 다 읽을 필요는 없어요. 어떤 파일을 만드는지만 보세요.

## 52 · 실습 1-2 ③ · 3단계 결과 보고 읽기
다 만들면 이런 보고가 옵니다. 하위 페이지, 이모지 아이콘, 검색, 블록 종류, 「/」 메뉴, 마크다운 단축키, 자동 저장, 다크 모드까지. 시킨 건 한 줄인데 기능 목록이 꽤 길죠. 그리고 정직하게 한 줄 덧붙입니다. 「직접 클릭해서 테스트하지는 못했습니다」. 확인은 우리 몫이라는 얘기예요.

## 53 · 실습 1-2 ③ · 4단계 브라우저로 보기
index.html을 브라우저로 열면 이 화면입니다. 생각보다 그럴듯하죠? 새 페이지도 만들어 보고, 「/」도 쳐 보고, 체크도 해 보세요. 그리고 이렇게 물어보세요. 이게 내가 원한 미니 노션인가?

## 54 · 한 줄 요청 결과
정리해 보면 이렇습니다. 시키지 않았는데 생긴 것, 검색, 이모지 아이콘, 하위 페이지, 다크 모드, 마크다운 단축키. 반대로 저는 블록을 끌어서 순서 바꾸는 걸 생각했는데, 그건 빠졌습니다. 그리고 이 모든 걸 누가 정했죠? 전부 AI입니다. 나쁜 결과는 아니에요. 다만 내 앱이 아니라 AI가 상상한 앱이죠. 그래서 1-3, 1-4에서 기획서와 개발 계획으로 내가 정하고, 1-6에서 다시 만들어 보겠습니다. 그 전에 방금 생긴 index.html은 지워 주세요. 기획 없이 만든 코드 위에 기획을 얹으면 섞이거든요. 화면은 머릿속에 잘 기억해 두시고요.
