# 1-2 도구 · 실습 환경 · 강사 대본

## 39 · 1-1 산출물 → 1-2
1-1 에서는 바이브코딩이 무엇인지 개념을 잡았습니다. 코드를 한 줄씩 직접 쓰는 대신, 만들고 싶은 것을 말로 맡기고 결과를 확인하는 방식이었죠. 개념은 잡았으니 이제 실제로 맡길 도구가 필요합니다. 1-2 에서는 계정 세 개를 만들고 프로그램을 설치해서, 다음 단원부터 바로 일할 수 있는 상태를 만들겠습니다.

> 곁들일 이야기 — 「vibe coding」이라는 말은 2025년 2월 Andrej Karpathy 가 처음 썼습니다. 그도 코드를 직접 들여다보기보다 말로 요청하고 결과를 보면서 고치는 방식을 이렇게 불렀는데, 그 방식을 하려면 결국 말을 받아 줄 도구가 있어야 합니다.

## 40 · 도구 · 실습 환경
이번 단원 제목은 「도구 · 실습 환경」입니다. 오늘 쓸 도구가 무엇이고 각각 어떤 일을 맡는지 먼저 보고, 뒤에서 직접 가입하고 설치합니다.

## 41 · 1부 커리큘럼
전체 순서에서 현재 위치를 한번 짚겠습니다. 1-1 에서 개념을 봤고, 지금이 1-2 도구 준비입니다. 이어서 1-3 기획서, 1-4 개발 계획, 1-5 Git 과 GitHub, 1-6 에서 실제 앱을 만들고, 1-7 에서 배포해 공유 주소를 얻습니다. 1-8 에서 돌아보고 2부로 넘어갑니다. 모든 단원은 「미니 노션」이라는 같은 예제로 먼저 보여 드리고, 여러분은 같은 순서로 자기 아이디어를 만듭니다.

> 곁들일 이야기 — 요리 수업을 떠올리시면 됩니다. 강사가 앞에서 김치찌개를 한 번 끓여 보이면, 수강생은 같은 순서로 자기가 고른 찌개를 끓입니다. 오늘 1-2 는 그중 장보기와 조리 도구 꺼내기에 해당합니다.

## 42 · 1부 실습 도구
1부에서 쓰는 도구는 네 개입니다. Claude 는 대화하면서 아이디어를 고를 때 씁니다. Claude Code 는 기획서, 개발 계획, 앱 코드까지 실제 파일을 만드는 일을 맡깁니다. GitHub 는 코드와 변경 기록을 보관하는 곳이고, Vercel 은 만든 앱을 인터넷 주소로 공개해 줍니다. 화살표 순서가 곧 1부의 작업 순서라고 보시면 됩니다.

> 곁들일 이야기 — 예를 들어 가게를 하나 연다고 하면, 상담 받을 사람(Claude), 실제로 공사해 줄 사람(Claude Code), 설계도와 공사 기록을 넣어 둘 창고(GitHub), 손님이 찾아올 간판과 주소(Vercel)가 각각 필요한 것과 비슷합니다.

## 43 · Claude
첫 번째 도구 Claude 입니다. claude.ai 웹사이트, 데스크톱 앱, 휴대폰 앱에서 쓸 수 있는 대화형 AI 입니다. 1부에서는 아이디어를 고르고 질문을 정리하는 일을 맡깁니다. 다만 Claude 는 대화창 안에서만 답하기 때문에, 내 컴퓨터 파일을 직접 고치거나 명령을 실행하지는 못합니다. 오른쪽 대화 예를 보시면, 「소크라테스식 대화로 진행해 줘」라고 요청했더니 답을 바로 주지 않고 「누가 쓰나요?」, 「끝낸 일은 지우나요?」처럼 질문을 하나씩 던집니다. 이렇게 질문에 답하다 보면 내가 만들 앱이 무엇인지 스스로 정리됩니다. 1-3 에서 이 방법을 그대로 씁니다.

> 곁들일 이야기 — 「소크라테스식 대화」라는 이름은 고대 그리스 철학자 소크라테스에서 왔습니다. 플라톤이 남긴 대화편을 보면 소크라테스는 답을 가르쳐 주기보다 상대에게 질문을 거듭해서 상대가 스스로 생각을 다듬게 합니다.
> 곁들일 이야기 — 일상에서는 휴대폰 매장 상담이 비슷합니다. 직원이 「주로 뭘 하세요? 사진 많이 찍으세요?」 하고 물어보면, 처음엔 막연하던 내 조건이 답하는 사이에 분명해집니다.

## 44 · Claude와 Claude Code
그러면 이름이 비슷한 Claude 와 Claude Code 는 무엇이 다를까요. 같은 요청 「미니 노션 만들어 줘」를 두 도구에 똑같이 해 보겠습니다. 위쪽 Claude 는 코드를 글로 답해 줍니다. 그다음은 사람이 코드를 복사하고, 파일을 만들어 붙여 넣고, 저장해서 브라우저로 열고, 오류가 나면 다시 물어봐야 합니다. 사람 손이 네 번 갑니다. 아래쪽 Claude Code 는 폴더 파일을 직접 읽고, index.html 을 만들고, 실행해서 확인하고, 오류도 직접 고칩니다. 사람은 마지막에 결과만 확인합니다. 차이는 한 가지, 내 컴퓨터 파일에 AI 손이 닿느냐입니다.

> 곁들일 이야기 — 예를 들어 전화로 요리법을 듣는 것과, 요리사가 우리 집 부엌에 와서 직접 요리하는 것의 차이입니다. 전화로는 아무리 정확히 알려 줘도 재료 손질과 불 조절은 내가 해야 합니다.
> 곁들일 이야기 — 엑셀 수식을 챗봇에 물어보고 답을 복사해 셀에 붙였는데 오류가 나서 다시 묻고, 또 붙여 넣는 경험을 해 보신 분이 많을 겁니다. 위쪽 줄이 바로 그 과정입니다.

## 45 · Claude Code 사용 환경
Claude Code 는 여러 곳에서 쓸 수 있습니다. 검은 명령어 창인 터미널에서 쓰는 방식이 기능이 가장 많고, VS Code 같은 편집기에서는 확장 프로그램으로, JetBrains 편집기에서는 플러그인으로 씁니다. macOS 와 Windows 용 데스크톱 앱도 있고, claude.ai/code 에서 웹으로 클라우드에서 돌릴 수도 있습니다. 어디서 쓰든 안에서 도는 엔진과 설정은 같습니다. 이 강의에서는 파일을 눈으로 보면서 작업할 수 있는 VS Code 를 기본으로 씁니다.

> 곁들일 이야기 — 카카오톡을 휴대폰에서 쓰든 PC 에서 쓰든 같은 계정, 같은 대화방이 보이는 것과 비슷합니다. 화면 모양만 다르고 안에 있는 것은 같습니다.

## 46 · VS Code
VS Code 화면은 네 구역으로 나뉩니다. 왼쪽 ① 탐색기는 폴더 안 파일 목록, 가운데 ② 편집기는 파일 내용을 보여 줍니다. 아래 ③ 터미널은 명령어를 입력하는 창이고, 오른쪽 ④ 가 Claude Code 와 대화하는 패널입니다. 여러분은 주로 ④ 에서 요청하고, ① 과 ② 에서 무엇이 바뀌었는지 확인하게 됩니다.

> 곁들일 이야기 — 윈도우 탐색기나 맥의 Finder 로 폴더를 열어 두고, 옆에 메모장을 띄워 두고, 그 옆에 메신저 창을 하나 더 열어 둔 모습을 한 화면에 모았다고 생각하시면 됩니다.
> 곁들일 이야기 — VS Code 는 Microsoft 가 무료로 배포하는 편집기입니다. 개발자들이 가장 많이 쓰는 편집기 가운데 하나라서, 막혔을 때 검색하면 자료를 쉽게 찾을 수 있습니다.

## 47 · 확장 프로그램
VS Code 는 처음 설치하면 기본 기능만 있고, 필요한 기능은 확장 프로그램으로 붙입니다. 휴대폰에 비유하면 VS Code 가 휴대폰, Marketplace 가 앱 스토어, 확장 프로그램이 앱입니다. 순서도 같습니다. ① 검색창에 이름을 치고, ② 목록에서 고르고, ③ Install 을 누릅니다.

> 곁들일 이야기 — 크롬 브라우저에 번역 기능이나 광고 차단 기능을 확장 프로그램으로 추가해 보신 분은 이미 같은 일을 해 보신 겁니다.

## 48 · Claude Code 확장 설치
실제로 Claude Code 확장을 설치하는 순서입니다. ① 왼쪽 확장 보기를 엽니다. 맥은 Shift·Command·X, 윈도우는 Ctrl·Shift·X 입니다. ② 검색창에 Claude Code 를 치고, 만든 곳이 Anthropic 인지 확인합니다. ③ Install 을 누르면 ④ 번개 모양 Spark 아이콘이 생기고, 그걸 눌러 로그인합니다.

> 곁들일 이야기 — 앱 스토어에서 은행 앱을 받을 때 비슷한 이름의 앱이 여러 개 뜨면 개발사 이름을 확인하고 받으시죠. 확장 프로그램도 같습니다. 이름이 비슷한 것이 여러 개 보일 수 있으니 「Anthropic」을 꼭 확인하세요.

## 49 · Claude Code 설치
VS Code 확장과 별개로, 터미널에서 쓰는 Claude Code 도 설치해 둡니다. 맥은 터미널에, 윈도우는 PowerShell 에 화면의 한 줄을 붙여 넣고 엔터를 누르면 됩니다. 설치가 끝나면 claude --version 을 입력해 버전 번호가 나오는지 봅니다. 번호가 나오면 설치된 것이고, claude 만 입력하면 실행됩니다. 윈도우를 쓰시는 분은 Git for Windows 도 함께 설치해 두시는 것이 좋습니다. 운영체제는 macOS 13 이상, Windows 10 1809 이상이어야 합니다.

> 곁들일 이야기 — 이렇게 인터넷 주소에서 설치 파일을 받아 바로 실행하는 한 줄 설치 방식은 꽤 흔합니다. 맥에서 프로그램 설치 도구로 많이 쓰는 Homebrew 도 공식 홈페이지에서 비슷한 한 줄 명령으로 설치합니다. 그래서 반드시 공식 문서에 있는 줄만 복사해야 합니다.

## 50 · 첫 실행과 로그인
설치했으면 처음 실행할 때 로그인합니다. claude 를 실행하거나 VS Code 확장을 열면 로그인 방법을 고르는 화면이 나옵니다. Claude 계정을 고르면 브라우저가 열려 인증하고, 이어서 「이 폴더에서 작업해도 되는지」 묻는 폴더 신뢰 화면이 나옵니다. 허용하면 입력창이 나오고 첫 요청을 보낼 수 있습니다. 로그인은 처음 한 번이면 되지만, 폴더 신뢰는 새 폴더를 열 때마다 묻습니다. 그리고 Free 계정은 로그인 단계에서 막힙니다. Pro 이상 계정이 필요합니다.

> 곁들일 이야기 — 휴대폰에 새 앱을 깔면 「사진에 접근해도 될까요?」 하고 묻죠. 폴더 신뢰도 같은 확인입니다. Claude Code 가 그 폴더의 파일을 읽고 고칠 수 있게 되니, 내가 작업할 폴더인지 보고 허용합니다.

## 51 · GitHub
세 번째 도구 GitHub 입니다. 인터넷에 둔 내 프로젝트 폴더라고 생각하시면 됩니다. 단순히 파일만 두는 것이 아니라 언제 무엇을 바꿨는지 변경 기록이 남습니다. 이 기록은 1-5 에서 자세히 다룹니다. 또 1-7 에서 배포할 때 Vercel 이 여기서 코드를 가져갑니다. 요금은 Free 로 충분하고, 비공개 저장소도 개수 제한 없이 만들 수 있습니다.

> 곁들일 이야기 — 구글 문서나 노션의 「버전 기록」을 열어 보면 어제 몇 시에 누가 어느 문장을 고쳤는지 나옵니다. GitHub 는 그 기능을 프로젝트 폴더 전체에 적용한 것에 가깝습니다.
> 곁들일 이야기 — GitHub 는 2018년에 Microsoft 가 인수했습니다. 앞에서 본 VS Code 와 같은 회사라서 두 도구가 잘 연결됩니다.

## 52 · Vercel
네 번째 도구 Vercel 입니다. 만든 앱을 「프로젝트이름.vercel.app」 같은 공개 주소로 올려 줍니다. 한 번 연결해 두면 GitHub 에 새로 올릴 때마다 자동으로 다시 배포합니다. 가입은 GitHub 계정으로 하기 때문에 비밀번호를 따로 만들 필요가 없습니다. 요금은 Hobby 가 무료인데, 개인 · 비상업용입니다. 회사 업무로 공개하려면 Pro, 월 20달러가 필요하다는 점은 기억해 두세요.

> 곁들일 이야기 — 무료 폰트를 쓸 때 「개인 사용 무료, 상업적 사용은 별도 라이선스」라는 조건을 보신 적이 있을 겁니다. Vercel Hobby 도 같은 구조입니다. 연습과 개인 프로젝트는 무료, 회사 일에 쓰면 유료입니다.
> 곁들일 이야기 — 「GitHub 로 계속하기」는 쇼핑몰에서 「카카오로 로그인」을 누르는 것과 같은 방식입니다. 새 아이디와 비밀번호를 만들지 않고 이미 있는 계정으로 들어갑니다.

## 53 · 실습 1-2
이제 직접 해 보겠습니다. 실습 1-2 의 목표는 세 가지입니다. 계정 세 개 만들기, Claude Code 설치하기, 그리고 할 일 목록 기능을 목표 한 줄로 맡겨 보기입니다. 순서는 가입, 설치, 내 폴더에서 첫 요청, 그다음 delegate_todo 폴더를 열어서 기능 세 개를 하나씩 맡기는 것입니다. 끝났는지는 세 가지로 판단합니다. claude --version 이 버전을 보여 주는지, 추가 · 체크 · 남은 개수가 브라우저에서 동작하는지, 그리고 그동안 코드를 직접 고치지 않았는지입니다.

> 곁들일 이야기 — 마지막 기준 「코드는 직접 고치지 않음」이 가장 지키기 어렵습니다. 예를 들어 오타 하나가 눈에 보이면 손이 먼저 가는데, 그것도 말로 맡겨 보는 연습입니다.

## 54 · 실습 1-2 ① 순서
첫 번째 순서는 가입과 설치입니다. claude.ai 에 가입하고 요금제를 확인합니다. github.com 에 가입하고, vercel.com 에서는 「GitHub 로 계속하기」를 누릅니다. 그다음 VS Code 를 설치하고 확장에서 Claude Code 를 설치합니다. 마지막으로 터미널에서 claude --version 을 입력합니다. 세 사이트 모두 로그인된 상태이고 VS Code 왼쪽에 Claude 아이콘이 보이면 다음으로 넘어갑니다. 자주 막히는 곳은 두 군데입니다. GitHub 가입 때 이메일 인증 코드를 확인하지 않아 진행이 멈추는 경우, 그리고 Vercel 에서 GitHub 가 아니라 이메일로 가입해 버리는 경우입니다.

> 곁들일 이야기 — 브라우저 탭 세 개를 나란히 열어 두고 각각 로그인된 상태를 눈으로 확인하는 것이 가장 빠른 점검 방법입니다.

## 55 · 실습 1-2 ① 준비
준비물을 한 번 더 정리합니다. 계정은 Claude Pro 이상, GitHub, Vercel 세 개입니다. 설치는 VS Code 와 Claude Code 확장입니다. 그리고 바탕화면에 폴더를 하나 만들어 주세요. 이름은 여러분이 만들고 싶은 아이디어 이름으로 짓습니다. 이 폴더가 1부 내내 쓸 작업 폴더가 됩니다. 폴더 이름은 띄어쓰기 없이 영어로 지으면 뒤에서 덜 헷갈립니다.

> 곁들일 이야기 — 회사에서 새 프로젝트를 시작할 때 공유 드라이브에 프로젝트 폴더부터 만들어 두는 것과 같습니다. 이후 나오는 기획서, 개발 계획, 앱 파일이 모두 이 폴더에 쌓입니다.

## 56 · 실습 1-2 ② 순서
두 번째 순서는 방금 만든 폴더에서 첫 요청을 보내는 것입니다. VS Code 에서 폴더 열기로 그 폴더를 열고, Claude Code 를 열어 로그인합니다. 폴더 신뢰를 묻는 창이 뜨면 허용합니다. 그리고 첫 요청을 보내고 답을 읽습니다. Claude Code 가 폴더 내용을 답하고, 파일이 새로 생기지 않았으면 성공입니다. 로그인 창이 안 뜨면 VS Code 를 껐다가 다시 켜 보세요. 또 파일 하나만 열고 폴더는 안 연 상태로 시작하는 경우가 많은데, 반드시 폴더째 여셔야 합니다.

## 57 · 실습 1-2 ② 요청 항목
첫 요청에는 세 가지를 담습니다. 목표는 이 폴더의 현재 상태를 듣는 것, 범위는 이 폴더 안만, 하지 말 것은 아직 파일을 만들지 않기입니다. 요청이 짧아도 「하지 말 것」을 한 줄 넣으면 AI 가 앞서 나가지 않습니다. 이 세 항목은 앞으로 모든 실습 요청에서 반복해서 씁니다.

> 곁들일 이야기 — 예를 들어 새로 온 동료에게 「이 공유 폴더에 뭐가 있는지만 먼저 훑어봐 줘. 아직 정리는 하지 말고」라고 말하는 것과 같습니다. 이 말 없이 「폴더 좀 봐 줘」만 하면, 의욕 있는 동료는 파일을 옮기고 이름까지 바꿔 놓기도 합니다.

## 58 · 첫 요청 결과
첫 요청 결과는 이렇게 나옵니다. 「이 폴더에 지금 뭐가 있는지 알려 줘. 아직 파일은 만들지 마」라고 하면, Claude Code 가 폴더가 비어 있고 파일도 하위 폴더도 없다고 답합니다. 만들 앱을 알려 주면 구조를 제안하겠다고 덧붙이기도 합니다. 여기서 점검할 것은 오른쪽 세 가지입니다. Pro 이상으로 로그인됐는지, claude --version 이 번호를 보여 주는지, 그리고 탐색기에 새 파일이 생기지 않았는지입니다. 하지 말라고 한 일을 정말 안 했는지 직접 확인하는 습관을 여기서부터 들입니다.

## 59 · 할 일 목록 예제
빈 폴더에서는 Claude Code 가 읽을 것이 없었습니다. 이번에는 강사가 미리 만들어 둔 미완성 할 일 목록 앱으로 위임을 연습합니다. 실습 파일 delegate_todo.zip 을 풀고 index.html 을 브라우저로 열면 할 일 두 개, 입력칸, 추가 버튼이 보입니다. 그런데 추가 버튼을 눌러도 아무 일도 없고, 체크해도 줄이 그어지지 않고, 남은 개수도 나오지 않습니다. 겉모양만 있고 동작은 비어 있는 상태입니다. 파일은 index.html, style.css, app.js 세 개입니다. 이 빈 동작을 Claude Code 에 말로 맡겨 채우는 것이 다음 실습입니다.

> 곁들일 이야기 — 모델하우스와 비슷합니다. 싱크대와 스위치는 다 달려 있는데 수도와 전기가 아직 연결되지 않은 상태입니다. 보이는 것과 동작하는 것은 따로라는 점을 직접 눌러 보며 느껴 보세요.

## 60 · 실습 1-2 ③ 순서
순서는 다섯 단계입니다. delegate_todo 폴더를 VS Code 로 열고, index.html 을 브라우저로 열어 추가 버튼을 직접 눌러 봅니다. 안 되는 것을 먼저 눈으로 확인하는 겁니다. 그다음 Claude Code 에 목표를 한 줄로 요청하고, 진행 화면에서 ① 읽기 ② 수정 ③ 확인 단계를 찾아봅니다. 끝나면 브라우저를 새로고침해서 직접 눌러 보고, 되면 다음 기능으로 넘어갑니다. 추가, 체크 줄 긋기, 「남은 할 일: N」 표시까지 세 개입니다. 가장 많이 막히는 곳은 새로고침입니다. Claude Code 가 고쳤는데도 버튼이 그대로라면 먼저 새로고침을 해 보시고, 그래도 안 되면 「추가 버튼을 눌러도 목록에 안 생긴다」처럼 보이는 증상을 그대로 전달하세요.

## 61 · 실습 1-2 ③ 요청 항목
요청 항목입니다. 목표는 기능 하나씩, 추가 → 체크 → 남은 개수 순서입니다. 확인 방법은 브라우저에서 직접 누르기입니다. 하지 말 것은 두 가지, 코드를 직접 고치지 않기, 그리고 세 기능을 한 번에 요청하지 않기입니다. 한 번에 맡기면 어느 하나가 안 될 때 어디서 틀렸는지 찾기 어렵습니다. 하나씩 맡기고 하나씩 확인하면 문제가 생겨도 바로 직전 요청만 보면 됩니다.

> 곁들일 이야기 — 예를 들어 집수리를 맡길 때 「욕실, 주방, 베란다 다 고쳐 주세요」라고 한꺼번에 맡기면, 나중에 물이 샐 때 어느 공사 때문인지 알기 어렵습니다. 욕실 끝나면 물 틀어 보고, 그다음 주방을 맡기는 쪽이 확인이 쉽습니다.

## 62 · Claude Code 작업 화면
요청하면 Claude Code 화면에 이런 답이 나옵니다. 「추가 버튼을 누르면 입력한 할 일이 목록에 생기게 해 줘」라고 하자, ① index.html 과 app.js 를 읽었고, ② app.js 에 추가 버튼 처리 코드를 넣었고, ③ 입력칸이 비면 추가하지 않게 했다고 답합니다. 맥락 파악, 작업, 결과 확인 세 단계가 보이시죠. 눈여겨볼 점은 ③ 입니다. 빈 입력 처리는 우리가 요청하지 않았는데 AI 가 덧붙였습니다. 이렇게 요청과 결과가 다를 수 있으니, 마지막은 항상 브라우저에서 직접 눌러 요청한 대로 되는지 확인합니다. 이것으로 1-2 를 마치고, 1-3 에서는 이 도구로 내 아이디어의 기획서를 만듭니다.

> 곁들일 이야기 — 배달 앱으로 음식을 시키면 요청 사항에 「맵게」라고 적어도, 받아서 한 입 먹어 보기 전에는 정말 맵게 왔는지 모릅니다. AI 가 「했다」고 답해도 확인은 내가 직접 해야 합니다.
