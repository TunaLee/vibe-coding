## 28 · 도구 · 실습 환경
이번 단원 제목은 「도구 · 실습 환경」입니다. 오늘 쓸 도구가 뭐고 각각 무슨 일을 맡는지 먼저 훑어보고, 뒤에서 직접 가입하고 설치합니다.

## 29 · 1부 커리큘럼
지도 한번 보고 가겠습니다. 1-1에서 개념을 봤고, 현재 1-2 도구 준비입니다. 이어서 1-3 기획서, 1-4 개발 계획, 1-5 Git과 GitHub, 1-6에서 드디어 앱을 만들고, 1-7에서 배포해서 공유 주소를 받습니다. 1-8에서 돌아보고 2부로 넘어가요. 모든 단원은 「미니 노션」이라는 같은 예제로 제가 먼저 보여 드리고, 여러분은 같은 순서로 자기 아이디어를 만듭니다.

> 곁들일 이야기 — 아까 요리 수업 이야기 했죠. 강사가 김치찌개를 한 번 끓여 보이면, 여러분은 같은 순서로 자기가 고른 찌개를 끓입니다. 그 기준으로 오늘 1-2는 장보기랑 냄비 꺼내기 단계예요. 아직 불은 안 켭니다.

## 30 · 1부 실습 도구
1부에서 쓰는 도구는 세 개뿐입니다. 아이디어 고르기부터 기획서, 개발 계획, 앱 코드까지 전부 Claude Code 하나로 합니다. 대화창 AI에서 아이디어 정리하고, 그걸 복사해서 다른 도구로 옮기고… 그런 거 안 합니다. 같은 일을 두 번 할 이유가 없으니까요. GitHub는 코드와 변경 기록을 보관하는 곳, Vercel은 만든 앱을 인터넷 주소로 공개해 주는 곳입니다. 화살표 순서가 그대로 1부 작업 순서예요. 이름이 다 영어라 벌써 머리 아프신 분, 세 개만 넘기면 더 안 늘어납니다.

> 곁들일 이야기 — 가게를 하나 연다고 해 보죠. 상담부터 공사까지 한 번에 해 주는 시공사(Claude Code), 설계도랑 공사 기록 넣어 둘 창고(GitHub), 손님이 찾아올 간판과 주소(Vercel). 상담 따로, 공사 따로 맡기면 같은 설명을 두 번 해야 하잖아요.

## 31 · Claude와 Claude Code
그럼 왜 굳이 Claude Code일까요. 이름이 거의 똑같은 Claude 대화창도 있는데요. 1-1 「AI 코딩 도구의 변화」에서 본 대화형과 위임형 차이입니다. 「미니 노션 만들어 줘」, 같은 요청을 두 도구에 똑같이 해 보겠습니다. 위쪽 Claude는 코드를 글로 답해 줍니다. 그다음부터는 사람 일이에요. 코드 복사하고, 파일 만들어 붙여 넣고, 저장해서 브라우저로 열고, 오류 나면 다시 물어보고. 사람 손이 네 번 갑니다. 아래쪽 Claude Code는 폴더 파일을 직접 읽고, index.html을 만들고, 실행해서 확인하고, 오류도 알아서 고칩니다. 사람은 마지막에 결과만 봐요. 차이는 딱 하나, 내 컴퓨터 파일에 AI 손이 닿느냐입니다. 그래서 이 강의는 처음부터 끝까지 Claude Code 하나로 갑니다.

> 곁들일 이야기 — 예를 들어 전화로 요리법을 듣는 것과, 요리사가 우리 집 부엌에 와서 직접 해 주는 것의 차이예요. 전화로는 아무리 친절하게 알려 줘도 양파는 내가 썰어야 합니다.
> 곁들일 이야기 — 엑셀 수식을 챗봇에 물어보고, 복사해서 셀에 붙였더니 오류, 다시 묻고 또 붙이고. 해 보신 분 많으시죠? 위쪽 줄이 바로 그 과정입니다.

## 32 · Claude Code 사용 환경
Claude Code는 쓰는 곳이 여러 군데입니다. 검은 명령어 창, 터미널에서 쓰는 방식이 기능이 제일 많고요. VS Code 같은 편집기에서는 확장 프로그램으로, JetBrains 편집기에서는 플러그인으로 씁니다. macOS랑 Windows용 데스크톱 앱도 있고, claude.ai/code에서 웹으로 클라우드에서 돌릴 수도 있어요. 어디서 쓰든 안에서 도는 엔진과 설정은 같습니다. 이 강의는 파일을 눈으로 보면서 작업할 수 있는 VS Code를 기본으로 갑니다. 검은 창이 무서우신 분들, 안심하셔도 됩니다.

> 곁들일 이야기 — 카카오톡을 휴대폰에서 쓰든 PC에서 쓰든 같은 계정, 같은 대화방이 보이잖아요. 화면 모양만 다르고 안에 있는 건 똑같습니다.

## 33 · VS Code
VS Code 화면은 네 구역입니다. 왼쪽 ① 탐색기는 폴더 안 파일 목록, 가운데 ② 편집기는 파일 내용. 아래 ③ 터미널은 명령어 치는 창이고, 오른쪽 ④가 Claude Code랑 대화하는 패널이에요. 여러분은 주로 ④에서 말을 걸고, ①과 ②에서 뭐가 바뀌었는지 확인하게 됩니다. 말은 오른쪽에서, 감시는 왼쪽에서. 이렇게 기억하시면 됩니다.

> 곁들일 이야기 — 윈도우 탐색기나 맥 Finder로 폴더를 열어 두고, 옆에 메모장 띄우고, 또 옆에 메신저 창 하나 더 열어 둔 모습을 한 화면에 모았다고 보시면 돼요.
> 곁들일 이야기 — VS Code는 Microsoft가 무료로 배포하는 편집기입니다. 개발자들이 가장 많이 쓰는 편집기 가운데 하나라서, 막혔을 때 검색하면 자료가 금방 나옵니다.

## 34 · 확장 프로그램
VS Code는 처음 깔면 기본 기능만 있고, 필요한 건 확장 프로그램으로 붙입니다. 휴대폰으로 치면 VS Code가 휴대폰, Marketplace가 앱 스토어, 확장 프로그램이 앱이에요. 순서도 같습니다. ① 검색창에 이름 치고, ② 목록에서 고르고, ③ Install 누르고. 앱 깔아 보신 분이면 이미 다 아시는 겁니다.

> 곁들일 이야기 — 크롬에 번역이나 광고 차단 기능을 확장 프로그램으로 붙여 보신 분? 그분들은 사실상 오늘 실습 하나를 미리 하신 겁니다.

## 35 · Claude Code 확장 설치
실제로 Claude Code 확장 까는 순서입니다. ① 왼쪽 확장 보기를 엽니다. 맥은 Shift·Command·X, 윈도우는 Ctrl·Shift·X예요. ② 검색창에 Claude Code 치고, 만든 곳이 Anthropic인지 꼭 확인합니다. ③ Install 누르면 ④ 번개 모양 Spark 아이콘이 생기고, 그걸 눌러서 로그인합니다.

> 곁들일 이야기 — 앱 스토어에서 은행 앱 받을 때 비슷한 이름이 여러 개 뜨면 개발사부터 보시잖아요. 확장 프로그램도 똑같습니다. 이름 비슷한 게 여럿 보일 수 있으니 「Anthropic」 꼭 확인하세요.

## 36 · Claude Code 설치
VS Code 확장이랑 별개로, 터미널에서 쓰는 Claude Code도 깔아 둡니다. 맥은 터미널에, 윈도우는 PowerShell에 화면의 한 줄을 붙여 넣고 엔터. 끝나면 claude --version을 쳐서 버전 번호가 나오는지 봅니다. 번호가 나오면 설치된 거고, claude만 치면 실행됩니다. 윈도우 쓰시는 분은 Git for Windows도 같이 깔아 두시는 게 좋아요. 운영체제는 macOS 13 이상, Windows 10 1809 이상이어야 합니다. 터미널 처음 열어 보시는 분, 한 줄 붙여 넣는 게 전부니까 겁먹지 않으셔도 돼요.

> 곁들일 이야기 — 이렇게 인터넷 주소에서 설치 파일을 받아 바로 실행하는 한 줄 설치, 꽤 흔한 방식입니다. 맥에서 많이 쓰는 설치 도구 Homebrew도 공식 홈페이지에서 비슷한 한 줄로 깔아요. 그러니까 더더욱, 반드시 공식 문서에 있는 줄만 복사하셔야 합니다.

## 37 · 첫 실행과 로그인
깔았으면 처음 실행할 때 로그인합니다. claude를 실행하거나 VS Code 확장을 열면 로그인 방법 고르는 화면이 나와요. Claude 계정을 고르면 브라우저가 열려서 인증하고, 이어서 「이 폴더에서 작업해도 될까요?」 묻는 폴더 신뢰 화면이 나옵니다. 허용하면 입력창이 나오고, 이제 첫 요청을 보낼 수 있어요. 로그인은 처음 한 번이면 되는데, 폴더 신뢰는 새 폴더 열 때마다 물어봅니다. 그리고 하나 미리 말씀드리면, Free 계정은 로그인 단계에서 막힙니다. Pro 이상이 필요해요.

> 곁들일 이야기 — 휴대폰에 새 앱 깔면 「사진에 접근해도 될까요?」 묻죠. 폴더 신뢰도 같은 확인입니다. 허용하면 Claude Code가 그 폴더 파일을 읽고 고칠 수 있게 되니, 내가 작업할 폴더가 맞는지 보고 누르세요.

## 38 · GitHub
세 번째, GitHub입니다. 인터넷에 둔 내 프로젝트 폴더라고 생각하시면 돼요. 그냥 파일만 두는 게 아니라 언제 뭘 바꿨는지 변경 기록이 남습니다. 이 기록 얘기는 1-5에서 제대로 하고요. 1-7에서 배포할 때 Vercel이 여기서 코드를 가져갑니다. 요금은 Free면 충분하고, 비공개 저장소도 개수 제한 없이 만들 수 있어요.

> 곁들일 이야기 — 구글 문서나 노션에서 「버전 기록」 열어 보면 어제 몇 시에 누가 어느 문장을 고쳤는지 다 나오죠. 「이거 누가 지웠어?」의 범인을 잡아 주는 그 기능을 프로젝트 폴더 전체에 붙인 게 GitHub라고 보시면 됩니다.
> 곁들일 이야기 — GitHub는 2018년에 Microsoft가 인수했습니다. 앞에서 본 VS Code와 같은 회사라 두 도구가 잘 붙어요.

## 39 · Vercel
네 번째, Vercel입니다. 만든 앱을 「프로젝트이름.vercel.app」 같은 공개 주소로 올려 줘요. 한 번 연결해 두면 GitHub에 새로 올릴 때마다 알아서 다시 배포합니다. 가입은 GitHub 계정으로 하니까 비밀번호를 또 만들 필요가 없고요. 비밀번호 하나 덜 외우는 것만 해도 어디예요. 요금은 Hobby가 무료인데, 개인 · 비상업용입니다. 회사 업무로 공개하려면 Pro, 월 20달러가 필요하다는 것, 이건 꼭 기억해 두세요.

> 곁들일 이야기 — 무료 폰트 받을 때 「개인 사용 무료, 상업적 사용은 별도 라이선스」 보신 적 있으시죠. Vercel Hobby도 같은 구조입니다. 연습이랑 개인 프로젝트는 무료, 회사 일에 쓰면 유료.
> 곁들일 이야기 — 「GitHub로 계속하기」는 쇼핑몰에서 「카카오로 로그인」 누르는 것과 같은 방식이에요. 새 아이디 만들 필요 없이 이미 있는 계정으로 들어갑니다.

## 40 · 실습 1-2
자, 이제 직접 해 볼 시간입니다. 실습 1-2는 화면 가운데 한 줄이 전부예요. 새 PC에서 시작해서, 한 줄 요청으로 만든 앱까지. 아래 칩 세 개가 순서입니다. 첫째, 계정 만들고 설치하고 작업 폴더 만들기. 둘째, 빈 폴더에서 Claude Code한테 첫 요청 해 보기. 셋째, 「미니 노션 만들어 줘」 한 줄만 던져 보기. 실습 파일은 workspace.zip 하나면 됩니다.

> 곁들일 이야기 — 마지막 기준, 「코드는 직접 고치지 않음」이 제일 어렵습니다. 예를 들어 오타 하나가 눈에 딱 보이면 손이 먼저 나가거든요. 그 손을 참고 말로 시켜 보는 게 오늘의 연습입니다.

## 41 · 실습 1-2 ① 순서
첫 번째는 가입과 설치입니다. claude.ai에 가입하고 요금제 확인. github.com 가입하고, vercel.com에서는 「GitHub로 계속하기」를 누릅니다. 그다음 VS Code 깔고, 확장에서 Claude Code 깔고, 마지막으로 터미널에서 claude --version. 세 사이트 다 로그인돼 있고 VS Code 왼쪽에 Claude 아이콘이 보이면 다음으로 넘어가시면 됩니다. 자주 막히는 데가 두 군데 있어요. GitHub 가입할 때 이메일 인증 코드를 안 봐서 진행이 멈추는 경우, 그리고 Vercel에서 GitHub 말고 이메일로 가입해 버리는 경우입니다. 「어, 안 넘어가는데요?」 하시면 십중팔구 이 둘 중 하나예요.

> 곁들일 이야기 — 브라우저 탭 세 개를 나란히 열어 두고, 각각 로그인돼 있는지 눈으로 보는 게 제일 빠른 점검법입니다.

## 42 · 실습 1-2 ① 준비
준비물 한 번 더 정리할게요. 계정은 Claude Pro 이상, GitHub, Vercel 세 개. 설치는 VS Code랑 Claude Code 확장. 그리고 바탕화면에 폴더 하나 만들어 주세요. 이름은 여러분이 만들고 싶은 아이디어 이름으로 짓습니다. 이 폴더가 1부 내내 쓸 작업 폴더예요. 이름은 띄어쓰기 없이 영어로 지으면 뒤에서 덜 헷갈립니다. 「새 폴더 (2)」만 피하셔도 절반은 성공이에요.

> 곁들일 이야기 — 회사에서 새 프로젝트 시작할 때 공유 드라이브에 폴더부터 하나 파 두잖아요. 같은 겁니다. 앞으로 나올 기획서, 개발 계획, 앱 파일이 전부 이 폴더에 쌓입니다.

## 43 · 실습 1-2 ① · 1단계 Claude 가입 · 요금제
첫 단계, Claude 가입입니다. claude.ai에 들어가서 Google 계정이나 이메일로 가입하시면 됩니다. 여기서 제일 중요한 건 요금제예요. 화면에 표시한 Pro 이상이어야 Claude Code를 쓸 수 있습니다. Free로 가입하면 가입까지는 잘 되는데, 나중에 Claude Code 로그인에서 딱 막힙니다. 「저만 안 돼요」의 1순위 원인이니까 지금 꼭 확인해 주세요.

## 44 · 실습 1-2 ① · 2단계 GitHub 가입

## 48 · 실습 1-2 ① · 5단계 설치 확인

## 49 · 실습 1-2 ① · 6단계 작업 폴더 구조
마지막 준비는 작업할 폴더입니다. 바탕화면에 workspace라는 폴더를 하나 만들고, 그 안에 실습 폴더를 모아 둡니다. mini_notion_v0는 이따 한 줄 요청으로 만들어 볼 앱, mini_notion은 오늘부터 1-7까지 키워 갈 내 앱 폴더예요. 기획서, 개발 계획, 앱 코드가 전부 mini_notion 안에 차곡차곡 쌓이고, 1부가 끝나면 이 폴더가 노션 같은 앱이 돼 있을 겁니다. VS Code로는 mini_notion 폴더를 엽니다. 폴더 이름은 영어 소문자와 밑줄로 지어 주세요. 나중에 저장소 주소에 그대로 들어가거든요. 귀찮으신 분은 workspace.zip을 받아 바탕화면에 풀면 이 구조가 한 번에 생깁니다.

## 50 · 실습 1-2 ① · 6단계 Windows 폴더 만들기
윈도우 쓰시는 분들. 파일 탐색기를 Win+E로 열고, 왼쪽에서 바탕 화면을 고른 뒤 Ctrl+Shift+N으로 새 폴더, 이름은 workspace. 들어가서 같은 방법으로 mini_notion을 만듭니다. 명령이 편하신 분은 PowerShell에 아래 두 줄을 붙여 넣으셔도 돼요. 여기서 윈도우만의 함정이 하나 있습니다. 회사 PC는 바탕 화면이 OneDrive 안에 들어가 있는 경우가 많아요. 그래서 「바탕화면에 만들었는데 왜 없지?」가 생기는데, 이 명령은 진짜 바탕 화면을 알아서 찾아갑니다. 폴더가 생기면 mini_notion을 우클릭해서 「Code(으)로 열기」, 메뉴가 안 보이면 VS Code에서 File, Open Folder로 여시면 됩니다.

## 51 · 실습 1-2 ① · 6단계 macOS 폴더 만들기
맥은 더 간단합니다. Finder에서 데스크탑으로 가서 Shift+Command+N으로 새 폴더, workspace. 안에 mini_notion. 터미널이 편하시면 아래 두 줄이면 끝나고요. zip으로 받으셨으면 더블클릭만 하면 같은 자리에 풀립니다. VS Code로 열 때는 mini_notion 폴더를 VS Code 아이콘 위에 끌어다 놓으면 바로 열려요. 이 방법, 의외로 모르는 분이 많습니다.

## 52 · 실습 1-2 ② 순서
두 번째는 방금 만든 폴더에서 첫 요청 보내기입니다. VS Code에서 폴더 열기로 그 폴더를 열고, Claude Code를 열어 로그인합니다. 폴더 신뢰 묻는 창이 뜨면 허용. 그리고 첫 요청을 보내고 답을 읽어 봅니다. Claude Code가 폴더 내용을 알려 주고, 파일이 새로 안 생겼으면 성공이에요. 로그인 창이 안 뜨면 VS Code를 껐다가 다시 켜 보세요. 그리고 파일 하나만 열고 폴더는 안 연 상태로 시작하시는 분이 꽤 많은데, 꼭 폴더째 여셔야 합니다.

## 53 · 실습 1-2 ② 요청 항목
첫 요청에는 세 가지를 담습니다. 목표는 이 폴더가 현재 어떤 상태인지 듣는 것, 범위는 이 폴더 안만, 하지 말 것은 아직 파일 만들지 않기. 요청이 짧아도 「하지 말 것」 한 줄을 넣으면 AI가 앞서 나가지 않아요. 이 세 항목, 앞으로 실습할 때마다 계속 씁니다. 지금 입에 붙여 두세요.

> 곁들일 이야기 — 예를 들어 새로 온 동료한테 「이 공유 폴더에 뭐 있는지만 먼저 훑어봐 줘. 정리는 아직 하지 말고」라고 하는 거죠. 이 말 없이 「폴더 좀 봐 줘」만 하면, 의욕 넘치는 동료는 파일 옮기고 이름까지 싹 바꿔 놓기도 합니다. 고맙긴 한데 내 파일을 못 찾아요.
