# 1-7 배포 · 강사 대본


## 146 · 1-6 산출물
1-6에서 드디어 미니 노션이 내 컴퓨터에서 돌아가기 시작했습니다. 뿌듯하시죠? 그런데 문제가 하나 있어요. 이 앱은 아직 내 노트북 안에서만 열립니다. 옆자리 동료한테 보여 주려면 노트북을 통째로 들고 가야 해요. 그래서 1-7에서는 이 앱에 인터넷 주소를 붙여서, 링크 하나로 누구한테나 보여 줄 수 있게 만듭니다. 1-7이 끝나면 손에 남는 건 공유 주소 하나입니다.

> 곁들일 이야기 — 개발자들 사이에 「제 컴퓨터에서는 되는데요(It works on my machine)」라는 아주 오래된 농담이 있습니다. 내 컴퓨터에서 잘 돌아가는 것과 남이 쓸 수 있는 건 전혀 다른 문제라는 뜻이에요. 오늘 그 차이를 메웁니다. 이제 여러분은 이 변명을 못 쓰게 됩니다.

## 147 · 배포
이번 단원 이름은 「배포」입니다. 말은 좀 거창하죠. 하는 일은 단순합니다. 내 앱을 남이 열 수 있게 내놓기, 그게 전부예요.

## 148 · 1부 커리큘럼
지도에서 현재 위치부터 보겠습니다. 1-3 기획서, 1-4 개발 계획, 1-5 첫 커밋, 1-6 동작하는 앱까지 왔고, 이제 1-7 배포입니다. 1-5에서 「GitHub는 왜 배우지?」 싶으셨던 분, 이번 단원에서 답이 나옵니다. GitHub에 올린 코드를 다른 서비스가 가져가서 공개해 주거든요. 늘 하던 대로 미니 노션으로 먼저 보여 드리고, 여러분은 같은 순서로 각자 앱을 올립니다.

## 149 · 배포
배포 전과 후를 나란히 놓고 보겠습니다. 배포 전 앱 주소는 localhost, 내 컴퓨터 안입니다. 열 수 있는 사람은 나 혼자고, 노트북을 덮으면 앱도 같이 잠듭니다. 배포를 하면 mini-notion.vercel.app 같은 주소가 생기고, 이 주소를 받은 사람은 누구나 열 수 있어요. 내 컴퓨터를 꺼도 앱은 계속 열립니다. 왜냐, 앱이 이제 내 컴퓨터가 아니라 인터넷에 있는 서버 위에서 돌아가니까요.

> 곁들일 이야기 — 예를 들어 회의에서 「제가 만든 메모장 한번 보세요」 하면서 노트북을 빙 돌려 보여 주는 게 배포 전이고, 단톡방에 링크 하나 올려서 각자 자기 휴대폰으로 열어 보게 하는 게 배포 후입니다. 노트북 돌리다 커피 쏟을 일도 없고요.

## 150 · 문서 파일과 공유 링크
더 익숙한 장면으로 바꿔 볼게요. 바탕화면에 있는 문서 파일은 내 컴퓨터에서만 열리죠. 이게 localhost입니다. 같은 문서를 온라인 문서 서비스에 올려서 공유 링크를 만들면, 팀장님도 팀원도 휴대폰으로도 열 수 있습니다. 이 공유 링크가 배포 주소, *.vercel.app에 해당해요. 그리고 문서를 고치면 링크로 보는 사람한테 바로 반영되죠. 배포에서는 이걸 재배포라고 부릅니다. 뒤에서 보겠지만 push만 하면 자동으로 됩니다.

> 곁들일 이야기 — 메일에 파일 첨부해서 돌리다 보면 「최종_진짜최종_v3.docx」 같은 파일이 여기저기 굴러다니죠. 다들 한 번씩 만들어 보셨을 겁니다. 공유 링크는 주소가 하나라서 모두가 항상 최신본을 봅니다. 배포 주소도 똑같아요. 고칠 때마다 새 파일을 돌리는 게 아니라 같은 주소의 내용이 바뀝니다.

## 151 · localhost · 내부망 · 외부망
그럼 정말로 내 컴퓨터의 앱은 다른 기기에서 못 여는 걸까요? 화면을 보시면 상자가 세 겹입니다. 맨 안쪽이 내 컴퓨터, 내 브라우저에서는 localhost:8000이 열립니다. 그 바깥이 공유기 안, 같은 Wi-Fi에 붙은 내부망이에요. 여기서는 내 컴퓨터의 내부 주소 192.168.0.12:8000으로 팀원 노트북이나 내 휴대폰에서도 열립니다. 생각보다 되죠? 그런데 집에 있는 사람이나 LTE로 접속한 휴대폰은 같은 주소를 쳐도 안 열립니다. 192.168로 시작하는 주소는 공유기 안에서만 통하는 주소거든요. 그래서 인터넷 어디서나 열리는 Vercel 서버에 올려 두고, mini-notion.vercel.app으로 열게 하는 겁니다.

> 곁들일 이야기 — 집 공유기 설정 들어갈 때 주소창에 192.168.0.1이나 192.168.1.1 쳐 보신 분 계실 거예요. 그 주소도 집 와이파이에 붙어 있을 때만 열립니다. 회사 프린터가 회사 Wi-Fi에서는 되는데 집에서는 안 되는 것도 같은 원리예요. 집에서 회사 프린터로 출력 눌러 본 분, 계시죠.

## 152 · 주소별 접속 범위
방금 본 주소 세 개를 표로 정리했습니다. localhost:8000은 이 컴퓨터만 열 수 있어서, 1-6에서 만들면서 확인할 때 썼죠. 192.168.0.12:8000 같은 내부 주소는 같은 Wi-Fi나 회사망 기기에서 열리니까, 배포 전에 내 휴대폰으로 화면 볼 때 쓸 수 있습니다. mini-notion.vercel.app은 인터넷의 누구나 열 수 있고, 남한테 공유할 때 씁니다. 참고로 192.168 같은 사설 주소 규칙은 RFC 1918이라는 인터넷 표준 문서에 정해져 있어요. 외울 필요는 없습니다.

> 곁들일 이야기 — localhost는 사실 127.0.0.1이라는 숫자 주소를 가리키는 이름입니다. 어느 컴퓨터에서든 「나 자신」을 뜻하는 주소라서, 개발자들은 「127.0.0.1만 한 곳은 없다(There's no place like 127.0.0.1)」라는 농담까지 만들었어요. 집만 한 곳이 없다는 말을 이렇게 바꿔 놓은 겁니다.

## 153 · 배포 흐름
그럼 배포가 실제로 어떤 길을 거치는지 보겠습니다. 내 컴퓨터에 앱과 커밋이 있고, 이걸 GitHub에 올립니다. 1-5에서 배운 코드 보관소죠. Vercel은 GitHub에 있는 코드를 가져가서 인터넷에 공개하고, *.vercel.app 주소를 줍니다. 다른 사람은 그 링크로 들어오고요. 우리가 할 연결은 딱 두 개입니다. 첫째, Claude Code가 gh라는 도구로 GitHub에 저장소를 만들고 올리게 하는 것. 둘째, GitHub와 Vercel을 한 번 이어 두는 것. 한 번 이어 두면 그다음부터는 알아서 굴러갑니다.

> 곁들일 이야기 — 블로그 글 하나를 여러 SNS에 자동으로 퍼 나르게 설정해 두는 것과 비슷합니다. 원본은 한 곳, GitHub에만 올리고, 공개하는 일은 연결된 서비스 Vercel이 알아서 합니다.

## 154 · GitHub CLI (gh)
첫 번째 연결에 쓰는 도구가 GitHub CLI, 줄여서 gh입니다. GitHub가 공식으로 만든 명령 도구예요. 웹사이트에서 버튼 눌러 하던 저장소 만들기, 올리기를 터미널 명령으로 할 수 있게 해 줍니다. 명령은 Claude Code가 실행하니까 외울 필요 없습니다. 우리가 할 일은 처음 한 번 설치하고 로그인해 두는 것뿐이에요. 맥은 brew install gh, 윈도우는 화면의 winget 명령으로 설치합니다. 하나만 기억하세요. 윈도우에서는 설치한 다음 터미널 창을 새로 열어야 gh를 알아봅니다. 열려 있던 창에서 「gh를 찾을 수 없다」고 나와도 당황하지 마세요. 설치가 실패한 게 아닙니다.

> 곁들일 이야기 — 새 프로그램을 깔았는데 아이콘이 안 보여서 재부팅하니까 보였던 경험, 한 번쯤 있으시죠. 터미널도 비슷합니다. 이미 열려 있던 창은 설치 전 상태를 기억하고 있어요. 새 창을 열어야 새로 깐 도구를 알아봅니다.

## 155 · gh 로그인
설치했으면 gh를 내 GitHub 계정이랑 연결합니다. 터미널에서 gh auth login을 실행하면 몇 가지를 묻는데, GitHub.com, HTTPS 같은 기본값을 고르면 됩니다. 그러면 화면에 짧은 코드가 나오고 브라우저가 열려요. 브라우저에 그 코드를 넣고 승인하면 「Logged in as 내계정」이 뜨면서 연결 끝입니다. 여기서 중요한 게 하나 있습니다. 브라우저 승인은 반드시 사람이 직접 합니다. 비밀번호를 Claude한테 알려 주지 않아요. Claude는 연결된 권한으로 명령만 실행합니다.

> 곁들일 이야기 — 거실 TV에서 넷플릭스나 유튜브 로그인할 때, TV에 뜬 코드를 휴대폰에 입력해 보셨죠? gh auth login도 같은 방식입니다. 리모컨으로 비밀번호 한 글자씩 치는 고행 대신, 이미 로그인된 휴대폰이나 브라우저에서 「이 기기 허락」만 누르는 겁니다.

## 156 · GitHub 업로드 요청
연결이 됐으면 이제 말로 시키면 됩니다. 「이 폴더를 GitHub 비공개 저장소 mini-notion으로 올려 줘」. 그러면 Claude가 gh repo create로 시작하는 명령을 보여 주면서 실행해도 되냐고 묻습니다. 「응」 하고 허락하면 GitHub에 저장소가 만들어지고, 지금까지의 커밋이 같이 올라간 다음 저장소 주소를 알려 줍니다. 명령은 몰라도 돼요. 다만 Claude가 허락을 구할 때 「private」이라는 단어가 들어 있는지 정도는 눈으로 확인하는 습관을 들이세요.

> 곁들일 이야기 — 은행 앱에서 이체 누르면 「받는 분 · 금액이 맞습니까」 하고 한 번 더 묻죠. 화면 내용을 다 이해 못 해도 받는 사람 이름 정도는 보고 누르잖아요. Claude가 명령 실행 전에 묻는 것도 같은 확인 단계입니다. 습관처럼 「응」만 누르면 은행 앱에서 그러는 것만큼 위험합니다.

## 157 · 공개 · 비공개 저장소
방금 요청에 굳이 「비공개」를 넣은 이유를 보겠습니다. 공개 저장소는 인터넷의 누구나 코드를 볼 수 있어요. 공개해도 괜찮은 연습 코드에 맞습니다. 비공개 저장소는 나와 내가 초대한 사람만 봅니다. 회사 업무나 이번 실습처럼 기획서와 개발 계획이 같이 들어가는 경우에는 비공개가 맞아요. 돈 걱정은 안 하셔도 됩니다. 무료 요금제인 GitHub Free에서도 비공개 저장소는 개수 제한 없이 만들 수 있고, 일부 기능만 유료입니다. 아끼려고 공개로 둘 이유가 없어요.

> 곁들일 이야기 — 구글 드라이브 공유 설정에서 「링크가 있는 모든 사용자」와 「특정 사용자만」 고르는 것과 같습니다. 회사 문서를 「모든 사용자」로 열어 뒀다가 식은땀 흘려 본 분도 계실 텐데요, 저장소도 기본은 비공개로 시작합니다.

## 158 · 업로드한 저장소 확인
올라갔으면 Claude가 알려 준 주소를 브라우저로 열어 봅니다. 볼 곳은 세 군데예요. 하나, 파일 목록이 내 폴더랑 같은지. index.html, style.css, app.js에 1-3의 기획서.md, 1-4의 개발계획.md까지 다 있어야 합니다. 둘, 커밋 기록에 1-5와 1-6에서 한 커밋들이 남아 있는지. 셋, 저장소 이름 옆에 자물쇠나 Private 표시가 있는지. 자물쇠가 보이면 비공개로 잘 올라간 겁니다.

> 곁들일 이야기 — 택배 보내고 송장 번호로 배송 조회 한 번 해 보는 거랑 같습니다. Claude가 「완료」라고 했어도, 직접 열어 보는 게 진짜 확인이에요.

## 159 · Vercel 프로젝트 가져오기
자, 이제 두 번째 연결, GitHub에서 Vercel로 넘어갑니다. 1-2에서 만든 GitHub 계정으로 Vercel에 로그인하고, 새 프로젝트에서 Git 저장소 가져오기를 고릅니다. 목록에서 mini-notion을 선택하고 Deploy를 누르면 끝이에요. 설정은 기본값 그대로 둡니다. 우리 앱은 HTML · CSS · JS 파일만 있는 폴더라서 빌드 설정을 건드릴 게 없거든요. 보통 1분 안팎이면 주소가 나옵니다. 제일 자주 막히는 곳은 목록에 내 저장소가 안 보이는 경우예요. 그럴 땐 GitHub 쪽에서 Vercel이 그 저장소에 접근하도록 허용해 줘야 합니다. 화면에 나오는 권한 설정 링크를 따라가서 저장소를 추가하세요.

> 곁들일 이야기 — 새로 깐 사진 편집 앱이 「사진 접근 허용」을 물을 때 「선택한 사진만」을 고르면, 나머지 사진은 앱에서 안 보이죠. Vercel도 똑같이 GitHub에서 허용받은 저장소만 볼 수 있습니다.

## 160 · 배포 주소
배포가 끝나면 주소가 두 종류 보입니다. 하나는 프로젝트 기본 주소, 프로젝트명.vercel.app 형식이에요. 우리 예제라면 mini-notion.vercel.app이죠. 다른 하나는 배포할 때마다 새로 생기는 고유 주소로, mini-notion-a1b2c3처럼 뒤에 글자가 붙습니다. 버전마다 따로 생기고 기본적으로 공개예요. 그럼 남한테는 뭘 보내느냐. 기본 주소입니다. 다시 배포해도 안 바뀌니까요.

> 곁들일 이야기 — 온라인 문서의 버전 기록을 떠올리시면 됩니다. 문서 링크는 하나지만, 버전 기록을 열면 과거 시점 모습을 따로 볼 수 있죠. 기본 주소는 항상 최신본, 배포마다 생기는 주소는 그 시점의 사본입니다.

## 161 · 배포 화면
이게 배포 주소로 연 미니 노션을 390px 휴대폰 폭에서 본 화면입니다. localhost에서 보던 거랑 코드는 똑같고 주소만 다릅니다. 개발 계획 완료 기준 마지막 줄 기억나세요? 「모바일 폭(390px)에서도 가로 스크롤 없이 보인다」. 배포했으니 이제 진짜 휴대폰으로 확인할 수 있어요. 주소를 메신저로 나한테 보내서 휴대폰으로 열어 보세요. 왼쪽 페이지 목록이 화면을 가리거나 글이 옆으로 삐져나가면, 1-6에서 했던 대로 화면 캡처해서 붙이고 고쳐 달라고 하면 됩니다.

> 곁들일 이야기 — 카카오톡 「나와의 채팅」에 주소를 보내 두면 휴대폰에서 바로 눌러 열 수 있습니다. 긴 주소를 손으로 옮겨 치다가 한 글자 틀려서 「사이트에 연결할 수 없음」 보는 일을 막아 줍니다.

## 162 · 수정 → 재배포
배포는 한 번으로 끝나지 않습니다. 앱은 계속 고치게 되거든요. 여기서 아까 연결해 둔 효과가 나옵니다. 화면 예처럼 「체크한 할 일 글자를 연한 초록으로」 같은 수정을 요청하고, localhost에서 확인한 다음, 「커밋하고 GitHub에 올려 줘」라고 말합니다. 그러면 push가 되고, Vercel이 그 push를 알아채서 1~2분 안에 새로 배포합니다. 결과는 같은 주소에 반영돼요. 이미 주소를 받은 사람한테 새 링크를 다시 보낼 필요가 없습니다. 정리하면 수정 요청, localhost 확인, 커밋과 push, 자동 배포, 같은 주소 반영. 다섯 단계입니다.

> 곁들일 이야기 — 식당 테이블에 QR 메뉴판 붙여 둔 가게는 메뉴가 바뀌어도 QR 스티커를 새로 뽑지 않습니다. QR이 가리키는 페이지 내용만 바꾸면 되죠. 배포 주소가 그 QR이고, push가 메뉴 페이지를 고치는 일입니다.

## 163 · 배포 전 점검
공개하기 전에 꼭 확인할 게 네 가지 있습니다. 첫째, 키나 비밀번호가 코드나 파일 안에 들어 있지 않은가. 둘째, 실제 사람 이름이나 연락처 같은 개인정보 대신 예시 값을 썼는가. 미니 노션처럼 회의록 다루는 앱이라면, 예시 페이지에 실제 회의 내용이나 동료 이름을 넣어 두지 않았는지도 봐야 해요. 셋째, 배포 주소는 공개입니다. 주소를 아는 사람은 누구나 열 수 있어요. 저장소를 비공개로 해도 배포된 앱 화면은 공개입니다. 여기서 많이들 헷갈립니다. 넷째, Vercel 무료 요금제인 Hobby는 개인 · 비상업용입니다. 회사 서비스로 쓰려면 Pro 이상이 필요해요. 점검은 Claude한테 맡기면 됩니다. 「올리기 전에 키 · 개인정보가 들어간 파일이 있는지 찾아 줘」, 한 줄이면 돼요.

> 곁들일 이야기 — 2022년 도요타가, 자사 서비스 소스 코드 일부가 외부 협력사 실수로 공개 저장소에 수년간 올라가 있었고 그 안에 데이터 서버 접근 키가 들어 있었다고 발표한 일이 있습니다. 그 큰 회사에서도 키가 코드에 섞여 공개되는 일이 생깁니다. 우리라고 예외일 리 없죠. 그래서 올리기 전에 한 번 찾아보는 단계를 습관으로 넣습니다.

## 164 · 실습 1-7
이제 직접 해 볼 차례입니다. 목표는 1-6에서 만든 내 앱을 GitHub에 올리고 Vercel 주소로 공개하는 것. 쓰는 폴더는 1-6의 내 앱 폴더입니다. 순서는 gh 설치와 로그인, Claude Code에 저장소 생성과 업로드 요청, Vercel에서 가져오기와 Deploy, 그리고 휴대폰으로 열어 보기. 마지막으로 한 곳을 고쳐서 push하고, 같은 주소에 반영되는지까지 봅니다. 완료 기준은 세 가지예요. 저장소에 내 파일과 커밋 기록이 있고, *.vercel.app 주소로 앱이 열리고, 수정 한 번이 재배포로 반영되면 끝입니다.

## 165 · 실습 1-7 순서
순서를 다섯 단계로 다시 짚겠습니다. 1번, 터미널에서 gh auth login 하고 브라우저에서 직접 승인. 2번, 올리기 전에 키와 개인정보 점검 요청. 3번, 저장소 만들고 올려 달라고 요청. 4번, Vercel에서 가져오기와 Deploy. 5번, 한 곳 고쳐서 커밋 · push 요청. 자주 막히는 곳은 두 군데입니다. 윈도우에서 gh를 못 찾는다고 나오면 터미널을 새로 여세요. Vercel 목록에 저장소가 없으면 GitHub 쪽 접근 허용을 확인하세요. 그 밖의 오류는요? 오류 문구를 그대로 복사해서 Claude한테 붙여 주면 됩니다.

> 곁들일 이야기 — 예를 들어 오류를 「뭔가 안 돼요」라고만 전하면 Claude도 짐작으로 답할 수밖에 없습니다. 고객센터에 전화해서 「그냥 안 돼요」 하는 것과 오류 코드를 불러 주는 것, 상담 속도가 다르잖아요.

## 166 · 실습 1-7 요청 항목
Claude한테 요청할 때 담을 항목입니다. 목표는 이 폴더를 GitHub에 올리기. 저장소는 이름을 정하고 비공개로. 올리기 전에 키와 개인정보 점검. 그리고 하지 말 것도 같이 말합니다. 기존 커밋을 지우지 말 것, 공개 저장소로 만들지 말 것. 하지 말 것을 미리 말해 두면, 중간에 문제가 생겼을 때 Claude가 커밋 기록을 정리해 버리는 식으로 우회하는 걸 막을 수 있어요.

> 곁들일 이야기 — 미용실에서 「다듬어만 주세요, 길이는 자르지 마세요」라고 하는 것과 같습니다. 「다듬어 주세요」만 했다가 거울 보고 놀란 경험, 다들 한 번쯤 있으시죠. 원하는 것만 말할 때보다 하지 말 것까지 말할 때 결과가 덜 어긋납니다.

## 167 · 실습 1-7 · 1단계 gh 로그인
배포 첫 단계는 GitHub와 내 컴퓨터를 연결하는 겁니다. 터미널에서 gh auth login. 브라우저가 열리면 화면에 나온 코드를 입력하고 승인하세요. 끝나면 gh auth status로 Logged in이 보이는지 확인합니다.

## 168 · 실습 1-7 · 2단계 올리기 전 점검
올리기 전에 꼭 하는 것, 키와 개인정보 점검입니다. 실제로 맡겨 봤더니 키나 비밀번호는 없다고 하면서, 커밋에 내 이메일이 들어 있다는 것까지 짚어 줬어요. 공개 저장소면 누구나 볼 수 있다고요. 화면의 이메일은 가렸습니다. 이런 건 사람이 놓치기 쉬운 부분이라 AI한테 점검을 맡기기 좋아요.

## 169 · 실습 1-7 · 3단계 저장소 만들고 올리기
「비공개 저장소로 만들어서 올려 줘」. 그러면 gh repo create 명령에 --private가 붙은 걸 보여 주고 허락을 구합니다. 비공개인지 여기서 한 번 더 확인하고 Yes.

## 170 · 실습 1-7 · 3단계 올린 결과
올라갔습니다. 저장소 주소가 나오고, GitHub에서 확인해 보니 비공개(PRIVATE)라고까지 알려 줘요. 이 주소를 브라우저로 열면 내 파일과 커밋 기록이 그대로 보입니다. 이제 Vercel이 여기서 코드를 가져갈 차례예요.

## 171 · 실습 1-7 · 4단계 Vercel 가져오기 · Deploy
vercel.com/new에 들어가면 내 GitHub 저장소 목록이 나옵니다. 방금 올린 저장소 옆 Import, 그리고 Deploy. 잠깐 기다리면 프로젝트이름.vercel.app 주소가 생깁니다. 목록에 저장소가 안 보이면 GitHub 접근 권한을 허용해 주세요.

## 172 · 실습 1-7 확인
다 했으면 네 가지를 확인합니다. 저장소 주소를 열어서 파일, 커밋, 자물쇠가 보이는지. 배포 주소가 PC와 휴대폰에서 둘 다 열리는지. push하고 1~2분 뒤 새로고침했을 때 고친 곳이 보이는지. 그리고 공개 전 점검에서 Claude Code가 키나 개인정보가 없다고 답했는지. 재배포가 안 보이면 1~2분 더 기다렸다가 새로고침을 한 번 더 해 보세요. 이렇게 얻은 배포 주소는 다음 1-8에서 결과 공유할 때 씁니다. 잘 적어 두세요.

> 곁들일 이야기 — 브라우저가 예전 화면을 기억하고 있어서 새로고침해도 그대로일 때가 있습니다. 「배포 안 됐잖아」 하고 Claude를 탓하기 전에, 시크릿 창이나 휴대폰으로 열어 보세요. 최신 화면인지 바로 구분됩니다.
