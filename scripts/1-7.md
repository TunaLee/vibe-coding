# 1-7 배포 · 강사 대본

## 159 · 1-6 산출물
1-6 에서 우리는 내 컴퓨터에서 실제로 돌아가는 미니 노션을 만들었습니다. 그런데 이 앱은 아직 내 노트북 안에서만 열립니다. 이번 1-7 에서는 이 앱에 인터넷 주소를 붙여서, 링크 하나로 누구에게나 보여 줄 수 있게 만듭니다. 1-7 이 끝나면 손에 남는 것은 공유 주소 하나입니다.

> 곁들일 이야기 — 개발자들 사이에 「제 컴퓨터에서는 되는데요(It works on my machine)」라는 오래된 농담이 있습니다. 내 컴퓨터에서 잘 돌아가는 것과 다른 사람이 쓸 수 있는 것은 별개라는 뜻인데, 오늘 그 차이를 메웁니다.

## 160 · 배포
이번 단원 이름은 「배포」입니다. 말은 어렵게 들리지만, 하는 일은 「내 앱을 남이 열 수 있게 내놓기」입니다.

## 161 · 1부 커리큘럼
지도로 현재 위치를 확인하겠습니다. 1-3 기획서, 1-4 개발 계획, 1-5 첫 커밋, 1-6 동작하는 앱까지 왔고, 이제 1-7 배포입니다. 1-5 에서 GitHub 를 배워 둔 이유가 이번 단원에서 드러납니다. GitHub 에 올린 코드를 다른 서비스가 가져가서 공개해 주기 때문입니다. 공통 예제인 미니 노션으로 먼저 보여 드리고, 여러분은 같은 순서로 각자의 앱을 올립니다.

## 162 · 배포
배포 전과 후를 나란히 놓고 보겠습니다. 배포 전 앱의 주소는 localhost, 즉 내 컴퓨터 안입니다. 열 수 있는 사람은 나 혼자이고, 노트북을 덮으면 앱도 같이 꺼집니다. 배포를 하면 mini-notion.vercel.app 같은 주소가 생기고, 그 주소를 받은 사람은 누구나 열 수 있습니다. 내 컴퓨터를 꺼도 앱은 계속 열립니다. 앱이 내 컴퓨터가 아니라 인터넷에 있는 서버 위에서 돌아가기 때문입니다.

> 곁들일 이야기 — 예를 들어 회의에서 「제가 만든 메모장 한번 보세요」 하면서 노트북을 돌려 보여 주는 것이 배포 전이고, 단톡방에 링크를 올려 각자 자기 휴대폰으로 열어 보게 하는 것이 배포 후입니다.

## 163 · 문서 파일과 공유 링크
익숙한 장면으로 바꿔 보겠습니다. 바탕화면에 있는 문서 파일은 내 컴퓨터에서만 열립니다. 이게 localhost 입니다. 같은 문서를 온라인 문서 서비스에 올리고 공유 링크를 만들면, 팀장도 팀원도 휴대폰으로도 열 수 있습니다. 이 공유 링크가 배포 주소, *.vercel.app 에 해당합니다. 그리고 문서를 고치면 링크로 보는 사람에게 바로 반영되죠. 배포에서는 이걸 재배포라고 부르는데, 뒤에서 보겠지만 push 만 하면 자동으로 됩니다.

> 곁들일 이야기 — 메일에 파일을 첨부해 보내면 「최종_진짜최종_v3.docx」 같은 파일이 여러 개 돌아다니게 되죠. 공유 링크는 주소가 하나라서 모두가 항상 최신본을 봅니다. 배포 주소도 같습니다. 고칠 때마다 새 파일을 돌리는 대신 같은 주소의 내용이 바뀝니다.

## 164 · localhost · 내부망 · 외부망
그럼 내 컴퓨터의 앱을 다른 기기에서는 정말 못 여는 걸까요. 화면을 보시면 상자가 세 겹입니다. 맨 안쪽이 내 컴퓨터로, 내 브라우저에서는 localhost:8000 이 열립니다. 그 바깥이 공유기 안, 같은 Wi-Fi 에 붙은 내부망입니다. 여기서는 내 컴퓨터의 내부 주소인 192.168.0.12:8000 으로 팀원 노트북이나 내 휴대폰에서도 열립니다. 그런데 집에 있는 사람이나 LTE 로 접속한 휴대폰은 같은 주소로 들어와도 열리지 않습니다. 192.168 로 시작하는 주소는 공유기 안에서만 통하는 주소이기 때문입니다. 그래서 인터넷 어디서나 열리는 Vercel 서버에 올려 두고, mini-notion.vercel.app 으로 열게 하는 겁니다.

> 곁들일 이야기 — 집 공유기 설정 화면에 들어갈 때 주소창에 192.168.0.1 이나 192.168.1.1 같은 주소를 쳐 본 분이 있을 겁니다. 그 주소도 집 안 와이파이에 붙어 있을 때만 열립니다. 회사 프린터를 회사 Wi-Fi 에서는 쓰는데 집에서는 못 쓰는 것과 같은 원리입니다.

## 165 · 주소별 접속 범위
방금 본 세 가지 주소를 표로 정리했습니다. localhost:8000 은 이 컴퓨터만 열 수 있어서, 1-6 에서 만들며 확인할 때 썼습니다. 192.168.0.12:8000 같은 내부 주소는 같은 Wi-Fi 나 회사망의 기기에서 열리니까, 배포 전에 내 휴대폰으로 화면을 볼 때 쓸 수 있습니다. mini-notion.vercel.app 은 인터넷의 누구나 열 수 있고, 남에게 공유할 때 씁니다. 192.168 같은 사설 주소의 규칙은 RFC 1918 이라는 인터넷 표준 문서에 정해져 있습니다.

> 곁들일 이야기 — localhost 는 실제로 127.0.0.1 이라는 숫자 주소를 가리키는 이름입니다. 「127.0.0.1 만 한 곳은 없다(There's no place like 127.0.0.1)」는 개발자 농담이 있을 정도로, 어느 컴퓨터에서든 「나 자신」을 뜻하는 주소입니다.

## 166 · 배포 흐름
배포가 실제로 어떤 길을 거치는지 보겠습니다. 내 컴퓨터에 앱과 커밋이 있고, 이걸 GitHub 에 올립니다. 1-5 에서 배운 코드 보관소입니다. Vercel 은 GitHub 에 있는 코드를 가져가서 인터넷에 공개하고, *.vercel.app 주소를 줍니다. 다른 사람은 그 링크로 들어옵니다. 우리가 할 연결은 두 개뿐입니다. 첫째, Claude Code 가 gh 라는 도구로 GitHub 에 저장소를 만들고 올리게 하는 것. 둘째, GitHub 와 Vercel 을 한 번 이어 두는 것. 이어 두면 그다음부터는 자동입니다.

> 곁들일 이야기 — 블로그 글 하나를 여러 SNS 에 자동으로 퍼 나르게 설정해 두는 것과 비슷합니다. 원본은 한 곳(GitHub)에만 올리고, 공개하는 일은 연결된 서비스(Vercel)가 알아서 합니다.

## 167 · GitHub CLI (gh)
첫 번째 연결에 쓰는 도구가 GitHub CLI, 줄여서 gh 입니다. GitHub 가 공식으로 만든 명령 도구로, 웹사이트에서 버튼으로 하던 저장소 만들기와 올리기를 터미널 명령으로 할 수 있게 해 줍니다. 명령은 Claude Code 가 실행하니까 외울 필요는 없습니다. 우리가 할 일은 처음 한 번 설치하고 로그인해 두는 것뿐입니다. 맥은 brew install gh, 윈도우는 화면의 winget 명령으로 설치합니다. 윈도우에서는 설치한 뒤 터미널 창을 새로 열어야 gh 를 알아봅니다. 열려 있던 창에서 「gh 를 찾을 수 없다」고 나와도 당황하지 마세요.

> 곁들일 이야기 — 새 프로그램을 깔았는데 바탕화면 아이콘이 안 보여서 재부팅하면 보이는 경험, 한 번쯤 있으시죠. 터미널도 비슷해서, 이미 열려 있던 창은 설치 전 상태를 기억하고 있습니다. 새 창을 열면 새로 설치한 도구를 알아봅니다.

## 168 · gh 로그인
설치했으면 gh 를 내 GitHub 계정과 연결합니다. 터미널에서 gh auth login 을 실행하면 몇 가지를 묻는데, GitHub.com 과 HTTPS 같은 기본값을 고르면 됩니다. 그러면 화면에 짧은 코드가 나오고 브라우저가 열립니다. 브라우저에서 그 코드를 입력하고 승인하면 「Logged in as 내계정」이 뜨면서 연결이 끝납니다. 여기서 중요한 점이 하나 있습니다. 브라우저 승인은 반드시 사람이 직접 합니다. 비밀번호를 Claude 에게 알려 주지 않습니다. Claude 는 연결된 권한으로 명령만 실행합니다.

> 곁들일 이야기 — 거실 TV 에서 넷플릭스나 유튜브에 로그인할 때, TV 화면에 뜬 코드를 휴대폰에 입력해 본 적이 있을 겁니다. gh auth login 도 같은 방식입니다. 리모컨으로 비밀번호를 치는 대신, 이미 로그인된 휴대폰이나 브라우저에서 「이 기기 허락」만 누르는 거죠.

## 169 · GitHub 업로드 요청
연결이 됐으면 이제 말로 요청합니다. 「이 폴더를 GitHub 비공개 저장소 mini-notion 으로 올려 줘」. 그러면 Claude 가 gh repo create 로 시작하는 명령을 보여 주면서 실행해도 되는지 묻습니다. 「응」 하고 허락하면, GitHub 에 저장소가 만들어지고 지금까지의 커밋이 함께 올라간 뒤 저장소 주소를 알려 줍니다. 명령을 몰라도 되지만, Claude 가 허락을 구할 때 「private」이라는 단어가 들어 있는지 정도는 눈으로 확인하는 습관을 들이세요.

> 곁들일 이야기 — 은행 앱에서 이체 버튼을 누르면 「받는 분 · 금액이 맞습니까」 하고 한 번 더 묻죠. 내용을 다 이해하지 못해도 받는 사람 이름 정도는 확인하고 누릅니다. Claude 가 명령 실행 전에 묻는 것도 같은 확인 단계입니다.

## 170 · 공개 · 비공개 저장소
방금 요청에서 「비공개」라고 말한 이유를 보겠습니다. 공개 저장소는 인터넷의 누구나 코드를 볼 수 있습니다. 공개해도 괜찮은 연습 코드에 맞습니다. 비공개 저장소는 나와 내가 초대한 사람만 봅니다. 회사 업무나 이번 실습처럼 기획서와 개발 계획이 함께 들어가는 경우에는 비공개가 맞습니다. 무료 요금제인 GitHub Free 에서도 비공개 저장소는 개수 제한 없이 만들 수 있고, 일부 기능만 유료입니다. 돈 걱정 때문에 공개로 둘 필요는 없습니다.

> 곁들일 이야기 — 구글 드라이브 공유 설정에서 「링크가 있는 모든 사용자」와 「특정 사용자만」을 고르는 것과 같습니다. 회사 문서를 「모든 사용자」로 열어 두면 안 되는 것처럼, 저장소도 기본은 비공개로 시작합니다.

## 171 · 업로드한 저장소 확인
올라갔다면 Claude 가 알려 준 주소를 브라우저로 열어 확인합니다. 볼 곳은 세 가지입니다. 파일 목록이 내 폴더와 같은지. index.html, style.css, app.js 와 1-3 의 기획서.md, 1-4 의 개발계획.md 까지 다 있어야 합니다. 커밋 기록에 1-5 와 1-6 에서 한 커밋들이 남아 있는지. 그리고 저장소 이름 옆에 자물쇠 표시나 Private 표시가 있는지. 자물쇠가 있으면 비공개로 잘 올라간 겁니다.

> 곁들일 이야기 — 택배를 보낸 뒤 송장 번호로 배송 조회를 한 번 해 보는 것과 같습니다. Claude 가 「완료」라고 했어도 직접 열어 보는 게 확인입니다.

## 172 · Vercel 프로젝트 가져오기
이제 두 번째 연결, GitHub 에서 Vercel 로 넘어갑니다. 1-2 에서 만든 GitHub 계정으로 Vercel 에 로그인하고, 새 프로젝트에서 Git 저장소 가져오기를 고릅니다. 목록에서 mini-notion 을 선택하고 Deploy 를 누르면 됩니다. 설정은 기본값 그대로 둡니다. 우리 앱은 HTML · CSS · JS 파일만 있는 폴더라서 빌드 설정을 바꿀 것이 없습니다. 보통 1분 안팎이면 주소가 나옵니다. 가장 자주 막히는 곳은 목록에 내 저장소가 안 보이는 경우입니다. 그럴 때는 GitHub 쪽에서 Vercel 이 그 저장소에 접근하도록 허용해 줘야 합니다. 화면에 나오는 권한 설정 링크를 따라가 저장소를 추가하세요.

> 곁들일 이야기 — 새로 깐 사진 편집 앱이 「사진 접근 허용」을 물을 때, 「선택한 사진만」을 고르면 나머지 사진은 앱에서 안 보이죠. Vercel 도 GitHub 에서 허용받은 저장소만 볼 수 있습니다.

## 173 · 배포 주소
배포가 끝나면 주소가 두 종류 보입니다. 하나는 프로젝트 기본 주소로, 프로젝트명.vercel.app 형식입니다. 우리 예제라면 mini-notion.vercel.app 이죠. 다른 하나는 배포할 때마다 새로 생기는 고유 주소로, mini-notion-a1b2c3 처럼 뒤에 글자가 붙습니다. 버전마다 따로 생기고 기본적으로 공개입니다. 남에게 공유할 주소는 기본 주소입니다. 다시 배포해도 바뀌지 않기 때문입니다.

> 곁들일 이야기 — 온라인 문서의 버전 기록을 떠올리면 됩니다. 문서 링크는 하나지만, 버전 기록을 열면 과거 시점의 모습을 따로 볼 수 있죠. 기본 주소는 항상 최신본, 배포마다 생기는 주소는 그 시점의 사본입니다.

## 174 · 배포 화면
이게 배포 주소로 연 미니 노션을 390px 휴대폰 폭에서 본 화면입니다. localhost 에서 보던 것과 코드는 같고 주소만 다릅니다. 개발 계획 완료 기준의 마지막 줄이 「모바일 폭(390px)에서도 가로 스크롤 없이 보인다」였죠. 배포했으니 이제 진짜 휴대폰으로 확인할 수 있습니다. 주소를 메신저로 나에게 보내 휴대폰에서 열어 보세요. 왼쪽 페이지 목록이 화면을 가리거나 글이 옆으로 삐져나가면, 1-6 에서 했던 대로 화면을 캡처해 붙이고 고쳐 달라고 요청하면 됩니다.

> 곁들일 이야기 — 카카오톡 「나와의 채팅」에 주소를 보내 두면 휴대폰에서 바로 눌러 열 수 있습니다. 주소를 손으로 옮겨 치다가 한 글자 틀리는 일을 막을 수 있습니다.

## 175 · 수정 → 재배포
배포는 한 번으로 끝나지 않습니다. 앱을 고치면 다시 배포해야 하는데, 여기서 연결을 해 둔 효과가 나옵니다. 화면의 예처럼 「체크한 할 일 글자를 연한 초록으로」 같은 수정을 요청하고, localhost 에서 확인한 뒤, 「커밋하고 GitHub 에 올려 줘」라고 말합니다. 그러면 push 가 되고, Vercel 이 그 push 를 알아채서 1~2분 안에 새 배포를 합니다. 결과는 같은 주소에 반영됩니다. 이미 주소를 받은 사람에게 새 링크를 다시 보낼 필요가 없습니다. 정리하면 수정 요청, localhost 확인, 커밋과 push, 자동 배포, 같은 주소 반영, 이 다섯 단계입니다.

> 곁들일 이야기 — 식당 입구에 QR 메뉴판을 붙여 둔 가게는 메뉴가 바뀌어도 QR 스티커를 다시 뽑지 않습니다. QR 이 가리키는 페이지 내용만 바꾸면 되죠. 배포 주소가 그 QR 이고, push 가 메뉴 페이지를 고치는 일입니다.

## 176 · 배포 전 점검
공개하기 전에 꼭 확인할 것이 네 가지 있습니다. 첫째, 키나 비밀번호가 코드나 파일 안에 들어 있지 않은가. 둘째, 실제 사람 이름이나 연락처 같은 개인정보 대신 예시 값을 썼는가. 미니 노션처럼 회의록을 다루는 앱이라면, 예시 페이지에 실제 회의 내용이나 동료 이름을 넣어 두지 않았는지도 봅니다. 셋째, 배포 주소는 공개라는 점. 주소를 아는 사람은 누구나 열 수 있습니다. 저장소를 비공개로 해도 배포된 앱 화면은 공개입니다. 넷째, Vercel 무료 요금제인 Hobby 는 개인 · 비상업용입니다. 회사 서비스로 쓰려면 Pro 이상이 필요합니다. 점검은 Claude 에게 맡기면 됩니다. 「올리기 전에 키 · 개인정보가 들어간 파일이 있는지 찾아 줘」 한 줄이면 됩니다.

> 곁들일 이야기 — 2022년 도요타가 자사 서비스 소스 코드 일부가 외부 협력사 실수로 공개 저장소에 수년간 올라가 있었고, 그 안에 데이터 서버 접근 키가 들어 있었다고 발표한 일이 있습니다. 큰 회사에서도 키가 코드에 섞여 공개되는 일이 생깁니다. 그래서 올리기 전에 한 번 찾아보는 단계를 습관으로 넣습니다.

## 177 · 실습 1-7
이제 직접 해 보겠습니다. 목표는 1-6 에서 만든 내 앱을 GitHub 에 올리고 Vercel 주소로 공개하는 것입니다. 쓰는 폴더는 1-6 의 내 앱 폴더입니다. 순서는 gh 설치와 로그인, Claude Code 에 저장소 생성과 업로드 요청, Vercel 에서 가져오기와 Deploy, 그리고 휴대폰으로 열어 보기입니다. 마지막으로 한 곳을 고쳐 push 하고 같은 주소에 반영되는지까지 봅니다. 완료 기준은 세 가지입니다. 저장소에 내 파일과 커밋 기록이 있고, *.vercel.app 주소로 앱이 열리고, 수정 한 번이 재배포로 반영되면 끝입니다.

## 178 · 실습 1-7 순서
순서를 다섯 단계로 다시 보겠습니다. 1번, 터미널에서 gh auth login 을 하고 브라우저에서 직접 승인합니다. 2번, 올리기 전에 키와 개인정보 점검을 요청합니다. 3번, 저장소를 만들고 올려 달라고 요청합니다. 4번, Vercel 에서 가져오기와 Deploy. 5번, 한 곳을 고쳐 커밋 · push 를 요청합니다. 자주 막히는 곳은 두 군데입니다. 윈도우에서 gh 를 못 찾는다고 나오면 터미널을 새로 여세요. Vercel 목록에 저장소가 없으면 GitHub 쪽 접근 허용을 확인하세요. 그 밖의 오류는 오류 문구를 그대로 복사해서 Claude 에게 붙여 주면 됩니다.

> 곁들일 이야기 — 예를 들어 오류를 「뭔가 안 돼요」라고 전하면 Claude 도 짐작으로 답할 수밖에 없습니다. 고객센터에 전화할 때 오류 코드를 불러 주면 상담이 빨라지는 것과 같습니다.

## 179 · 실습 1-7 요청 항목
Claude 에게 요청할 때 담을 항목입니다. 목표는 이 폴더를 GitHub 에 올리기. 저장소는 이름을 정하고 비공개로. 올리기 전에 키와 개인정보 점검. 그리고 하지 말 것도 같이 말합니다. 기존 커밋을 지우지 말 것, 공개 저장소로 만들지 말 것. 하지 말 것을 미리 말해 두면, 중간에 문제가 생겼을 때 Claude 가 커밋 기록을 정리해 버리는 식의 우회를 막을 수 있습니다.

> 곁들일 이야기 — 미용실에서 「다듬어만 주세요, 길이는 자르지 마세요」라고 말하는 것과 같습니다. 원하는 것만 말할 때보다 하지 말 것을 같이 말할 때 결과가 덜 어긋납니다.

## 180 · 실습 1-7 확인
다 했으면 네 가지를 확인합니다. 저장소 주소를 열어 파일, 커밋, 자물쇠가 보이는지. 배포 주소가 PC 와 휴대폰에서 모두 열리는지. push 하고 1~2분 뒤 새로고침했을 때 고친 곳이 보이는지. 그리고 공개 전 점검에서 Claude Code 가 키나 개인정보가 없다고 답했는지. 재배포가 안 보이면 1~2분 기다린 뒤 새로고침을 한 번 더 해 보세요. 이렇게 얻은 배포 주소는 다음 1-8 에서 결과를 공유할 때 씁니다. 잘 적어 두세요.

> 곁들일 이야기 — 브라우저가 예전 화면을 기억하고 있어서 새로고침해도 그대로일 때가 있습니다. 그럴 때는 시크릿 창이나 휴대폰으로 열어 보면 최신 화면인지 바로 구분됩니다.
